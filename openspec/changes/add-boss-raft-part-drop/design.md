# Design

## Context

- 現状(setup-side-scroller でアーカイブ済み): `src/core` にプレイヤー・カメラ・ループのロジックがあり、`src/main.ts` が `stepPlayer` だけを呼んでいる。ゲーム状態をまとめる層はまだない。
- 動機とスコープは proposal.md を参照。要件は specs(`boss-enemy` / `raft-part-collection`)を参照。
- プロジェクト方針: ロジックは `src/core`(DOM/Canvas 非依存、Vitest でテスト)、描画・入力は `src/platform`。

## Goals / Non-Goals

**Goals:**
- ボス・部品・所持数を純粋なロジックとして実装し、1 回の更新(`stepGame`)で決定的に進める
- 後続の change(ボス・部品の追加、プレイヤーHP、イカダ完成)がデータを足すだけで拡張しやすい形にする

**Non-Goals:**
- 汎用 ECS、ボスのデータ駆動化(ボス複数化を扱う change で検討)
- 「こびとづかん」の既存設定の再現(名前のみ使い、見た目・挙動は独自のプレースホルダー)
- プレイヤーのHP、ゲームオーバー、クリア判定

## Decisions

### 1. ゲーム状態を `GameState` にまとめ、`stepGame` で更新する
```
src/core/
  game.ts         # GameState, createGame(), stepGame(state, input, dt)
  boss.ts         # Boss 状態、往復移動、ダメージ/無敵/撃破
  raft-part.ts    # RaftPart 状態、落下
  collision.ts    # AABB 重なり判定、踏みつけ判定、押し戻し
```
- `GameState = { player, boss, parts: RaftPart[], partsCollected: number }`。イミュータブルに新しい状態を返す(既存 `stepPlayer` と同じ流儀)。
- `main.ts` は `stepGame` を呼び、`state` を `Renderer` に渡すだけにする。
- 代替: `main.ts` に更新順序を直接書く案は、ロジックがテストできなくなるため却下。

### 2. 1 回の更新の順序
1. `stepPlayer`(入力・移動・重力・着地)
2. `stepBoss`(往復移動、無敵タイマー減算)
3. プレイヤーとボスの衝突解決(踏みつけ / 押し戻し)
4. ボスの体力が 0 になった更新で、部品を 1 個スポーン(撃破の遷移でのみ。再スポーン防止)
5. `stepPart`(重力で落下、地面で静止)
6. プレイヤーと部品の重なり判定 → 拾得(`parts` から除去、`partsCollected++`)
- 順序を固定することで、テストで「どの更新で何が起きるか」を決定的に書ける。

### 3. 踏みつけ判定は「前フレームの下辺」で行う
- 踏みつけ条件: プレイヤーが矩形として重なっている、かつ `player.vy > 0`(落下中)、かつ **更新前のプレイヤー下辺がボス上辺 + 許容量(8px)以内**。
- 現在位置だけで判定すると、落下が速いときに側面接触と区別できず、すり抜けや誤判定が起きるため、更新前の位置を使う(`stepGame` が更新前の `player` を保持)。
- 踏みつけ成立時: プレイヤー下辺をボス上辺に合わせ、`vy = -STOMP_BOUNCE_SPEED`、`onGround = false`。ダメージはボスが無敵でないときのみ `hp -= 1` し、無敵タイマーを `BOSS_INVULN_TIME` にする。
- 無敵中の踏みつけは、ダメージなしで跳ね返りだけ与える(押し戻しに落ちると不自然なため)。
- 跳ね返りは `onGround = false` で上向き速度を与えるだけなので、`player-movement` の二重ジャンプ禁止(`onGround` が条件)とは干渉しない。

### 4. 側面接触は最小侵入方向への押し出し
- 踏みつけ条件を満たさない重なりは、水平方向の最小侵入量だけプレイヤーをボスの反対側へ移動する(ボス中心との相対位置で向きを決める)。ダメージ・ノックバック速度は与えない(ゲーム性の調整は後続)。
- 押し出し後のプレイヤー x はワールド範囲にクランプする。ボスは範囲内を往復するため、プレイヤーがボスと壁の間に挟まって抜けられなくなることは現状の配置では起きない。
- 撃破済みのボスは衝突判定の対象外。

### 5. ボスの往復
- `Boss = { x, y, vx, hp, invuln, alive, left, right }`。`x` が `[left, right]` を出る更新で `vx` の符号を反転し、範囲内に戻す。速度は 80 px/s、体力 3、サイズ 80×100(config に集約)。
- 初期配置: ワールド x = 1800 付近、往復範囲 `[1600, 2000]`。プレイヤー初期位置(x=100)から歩いて到達できる距離。

### 6. 部品とドロップ
- `RaftPart = { x, y, vy, grounded }`。ドロップ位置はボス中心(撃破時の位置)。サイズ 24×24。
- 落下は既存の `GRAVITY` を使い、`GROUND_Y` で静止(`grounded = true`、以降は更新しない)。
- 拾得はプレイヤーとの AABB 重なり(落下中でも可)。拾得した部品は配列から除去する。
- 所持は現状は数だけ(`partsCollected`)。部品の種類が増える change で、種別ごとの所持へ拡張する。

### 7. HUD は画面座標で描画する
- `Renderer.draw(state, cameraX)` の最後に、カメラ変換を使わず画面座標の固定位置へ「イカダの部品: N」を描画する。ボス・部品は既存の `worldToScreen` で描画する。
- ボスは赤系以外の色(例: 緑)、部品は黄色の小さな四角形で、プレイヤー(赤)と区別する。ボスには体力が分かるよう、頭上に小さな残り体力バーを出す(図形のみ)。
- テキストは Canvas の `fillText`。フォントは `sans-serif` 系のシステムフォントを使い、画像アセットは使わない。

### 8. 既存 spec・コードへの影響
- `player-movement`、`camera-follow`、`game-loop` の要件は変更しない。
- `stepPlayer` は変更しない。跳ね返りは `stepGame` 内でプレイヤー状態を書き換えて実現する。

## Risks / Trade-offs

- [踏みつけ判定の許容量(8px)が大きすぎる/小さすぎると、踏んだのに被ダメ扱い、またはその逆になる] → 許容量を `config` の定数にし、テストで「許容量内/外」を確認、手動プレイで調整する。
- [ボスの体力・速度・無敵時間が体感に合わない] → すべて `config.ts` に集約し、手動プレイで調整する。
- [ダメージのない側面接触は緊張感に欠ける] → 現段階では許容。プレイヤーのHPは後続の change で扱う。
- [「こびとづかん」の既存キャラクターを扱う知的財産上の注意] → 個人学習用・ローカル実行のみで、名前の参照と図形の代用に留める。画像・音・設定文の転用や公開はしない。公開する場合は事前に権利を確認する。

## Open Questions

- ボスの往復範囲、体力、無敵時間、跳ね返りの強さの最終値は、実際に遊んで調整する(spec には影響しない)。
