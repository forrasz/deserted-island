# Design

## Context

- 先行入力は `src/core/player.ts` の `stepPlayer` にある。着地できない間のジャンプ押下で `jumpBuffer = JUMP_BUFFER(0.1 秒)` をセットし、`jumpBuffer > 0 && grounded` で、キーの押下に関係なくジャンプする。着地前にキーを離していると、同じ更新の「離したら打ち切る」処理で、上向きの速さが毎秒 400 に切られて、低い小ジャンプになる。
- 足元は、シートの各コマの `fy`(足の下端)を、矩形の下辺に合わせて描いている(`src/platform/renderer.ts` の `drawPlayer`)。`fy` は `tools/build-player-sheet.mjs` が、不透明な画素の下端から求めたもの。靴の下に残った影・ほこり・薄い残り(背景除去のあと)があると、本当の足の下端より下を足元としてしまい、浮いて見える。または、倍率の丸め・矩形の下辺の描画位置のずれも考えられる。原因は、まだ測っていない。

## Goals / Non-Goals

**Goals:**
- 全コマで、靴の底が地面の上面に密着して見える(誤差 1 px 以内)。
- 階段を登るときの着地で、意図しない小ジャンプが起きない。

**Non-Goals:**
- 当たり判定(矩形・踏みつけ)の変更。
- 可変ジャンプ・コヨーテタイムの変更。
- 絵そのものの描き直し。

## Decisions

1. **先行入力は、着地の瞬間にキーを押し続けているときだけ使う。** 着地できない間にキーを離したら、`jumpBuffer` を 0 にする。着地の更新で `jumpBuffer > 0 && input.jump && grounded` のときだけ、バッファによるジャンプにする。
   - 代案 A: 先行入力を廃止する → 連続ジャンプ(押し続けて着地で即ジャンプ)の気持ちよさが失われ、直前の変更(マリオ風ジャンプ)の趣旨に反するため採らない。
   - 代案 B: 時間を短くする(0.1 → 0.05 秒) → 小ジャンプの頻度が減るだけで、なくならないため採らない。
2. **足元は、実画面でコマごとに測って直す。** 各コマで、描画された靴の底の最も下の画素が、矩形の下辺と一致するかを測る(ブラウザのスクリーンショットから)。ずれの原因が `fy` の求め方なら、ツールで、影・ほこりを除いた足の下端を求めるように直し、シートを作り直す。原因が描画側なら、`drawPlayer` を直す。どちらでも、表示の仕様(高さ 70 px・足の中心と下端の位置)は変えない。
3. 足元の検査は、ツールのテスト(または、コマの一覧の検査)でも行う: 地上の動きの全コマで、`fy` が、矩形の下端に近い(靴の底の位置)こと。

## Risks / Trade-offs

- 着地の直前にキーを押して離す「軽いタップの先行入力」は、効かなくなる。連続でジャンプするには、着地まで押し続ける必要がある(従来のゲームの多くと同じ)。
- シートの作り直しで、コマの見た目が少し変わる可能性がある(足元の位置が、数 px 動く程度)。

## 実装での確認結果

- 実画面(平地)で、待機・歩く・走るの全コマの、靴の底の最も下の画素は、地面の上面と一致していた(隙間 0)。当初の見立てのうち「`fy` の求め方のずれ」は確認できなかった。残る原因は、靴の縁の半透明の画素と、画素の丸めによる、1 px 程度の浮きと判断し、足元を 1 px だけ沈める(`PLAYER_FOOT_SINK = 1`)ことで密着させた。
- 地上の全コマで、足の下端の下の透明な余白が、表示で 2 px 以内であることを、実際の `playersheet.json` で検査する。
