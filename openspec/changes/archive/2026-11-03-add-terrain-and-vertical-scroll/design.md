# Design

## Context

- 現状: 地面は 1 本の水平線(`groundY` = 460)で、プレイヤー(`stepPlayer`)・部品(`stepPart`)・ボス(`createBoss`)・描画(`renderer.ts`)がそれぞれ `groundY` / `GROUND_Y` を使って「床」を決めている。ワールドは幅 3840・高さ 540(画面と同じ)で、カメラは横のみ。
- `WorldBounds { width, groundY }` が、プレイヤー・ゲーム更新のテストに広く使われている。
- 動機とスコープは proposal.md、要件は specs(`terrain` / `stage-layout`、`camera-follow` と `player-health` への追加)を参照。

## Goals / Non-Goals

**Goals:**
- 崖(壁)と浮島(一方通行の足場)と穴を、純粋なロジックとして実装し、Vitest で検証できるようにする
- 既存のテスト・既存のゲーム(平らな地面)を壊さないよう、地形を省略した `WorldBounds` は従来の平地として動かす
- ステージが最後まで到達可能であることを、構造の制約と物理シミュレーションの両方で検証する

**Non-Goals:**
- 移動する足場、壊れる足場、地形ダメージ、はしご、浮島を下に降りる操作
- ステージの最終的な長さの調整(後続の change で敵を置いてから行う)
- 地形の画像素材、背景の縦視差

## Decisions

### 1. 地形は「崖(solids)」と「浮島(platforms)」の矩形の集合
```ts
interface WorldBounds {
  width: number;
  groundY: number;        // 地面の上面。ボス・部品の床にも使う(平地の区間)
  height?: number;        // ステージの高さ
  solids?: Rect[];        // 崖と、穴で分割された地面(通れない)
  platforms?: Rect[];     // 浮島(上からのみ着地)
}
```
- 地面は「穴で分割された、上面が `groundY` の `solids`」として表す(各区間は上面から世界の下端まで)。穴は、隣り合う地面区間の間の隙間。
- `solids` を省略した `WorldBounds`(既存テストが使っている形)は、「x=0 から `width` まで上面が `groundY` の 1 枚の地面」として扱う。これにより、既存のテストの多くは変更なしで通る。
- ボス・部品は引き続き `groundY` を床にする。そのため、ボスの闘技場(部品が落ちる範囲)は平地にする(stage-layout の要件)。
- 代替: 地形をタイルの 2 次元配列にする案は、幅 16800 では大きく、描画・判定の見通しが悪いため却下。矩形の集合は、手書きと検証が容易。

### 2. プレイヤーの衝突解決(`terrain.ts`):水平 → 垂直の順
`stepPlayer` を次の順に変更する(地形が平地のときは従来と同じ結果になる)。
1. 入力から `vx`、ジャンプ(`onGround` のときのみ)と重力で `vy` を決める。`vy` は落下速度の上限(`MAX_FALL_SPEED = 1500` px/s)で頭打ちにする。
2. **水平**: `x += vx·dt`、ワールドの左右端にクランプ。`solids` と重なったら、移動方向と逆側へ押し出す(右へ動いて重なったら崖の左面へ、左なら右面へ)。重なりは「面積を持って」判定する(辺が接するだけでは重ならない)ので、崖や床の上に立っているだけでは水平の押し出しは起きない。
3. **垂直**: `y += vy·dt`。落下中(`vy > 0`)なら、更新前の下辺が上面以上で、更新後の下辺が上面を超えた `solids` と `platforms` の上面に着地する(最も高い上面)。更新前の下辺を使うので、薄い足場も、高速で落ちても、すり抜けない。上昇中(`vy < 0`)なら、更新前の上辺が下面以下で、更新後の上辺が下面を超えた `solids` の下面で頭をぶつけ、`y` を下面に合わせて `vy = 0` にする(浮島は通り抜ける)。
4. 着地した更新で `onGround = true`、`vy = 0`、`y` を上面に合わせる。浮島の側面・下面では何も起きない。
- 床の浮動小数の誤差には、許容量(0.01)を持たせる。
- 代替: 位置を細かく刻んで掃引する案は、現状の速度・足場の厚みでは不要。更新前の位置を使う判定で足りる。

### 3. 穴への落下と復帰(`game.ts`)
- 落下ライン `fallY = height + 60`(ステージの下端から画面外へ十分出た位置)。`stepPlayer` 後に `player.y > fallY` なら落下とする。
- `GameState` に `respawn: { x, y }`(復帰用の安全な位置)を追加する。初期値はスタート位置。
- **記録**: 更新後に `player.onGround` で、かつ足元の幅全体(`x` 〜 `x + PLAYER_WIDTH`)が、1 つの足場(崖・浮島・地面の区間)の上面に支えられているときだけ、その位置を `respawn` に記録する。穴や足場の縁(一部しか支えられていない)では更新しない。
- **復帰**: 落下したら `hp = max(0, hp - 1)`、`player = { x, y } = respawn`(速度 0、`onGround = true`)、`hitInvuln = PLAYER_INVULN_TIME`、`dead = (hp <= 0)`。落下による被弾は、被弾後の無敵の最中でも発生する(無敵の有無を見ない)。復帰後の無敵は、復帰位置に再び落ちないための猶予でもある。
- 既存のボス接触・踏みつけ・拾得・脱出の順序は変えない。落下判定は `stepPlayer` の直後(ボス衝突の前)に行う。
- **復帰直後の操作不能時間**: 復帰位置は穴の縁に近いことがある(縁から約 44px)。復帰後も方向キーを押し続けていると、人間の反応時間では間に合わず、続けて落ちてゲームオーバーになる(実際に、約 2 秒で 3 回落ちることをブラウザで確認した)。そこで、復帰直後の 0.4 秒(`RESPAWN_LOCK_TIME`)は入力を受け付けない(`GameState.respawnLock`)。この間にキーを離せる。
- 復帰位置の近くにボスがいる場合がありうるが、復帰後の無敵があるため、すぐには被弾しない。

### 4. カメラの縦追従(`camera.ts`)
- `computeCameraY(playerCenterY, viewHeight = VIEW_HEIGHT, worldHeight = WORLD_HEIGHT) = clamp(playerCenterY - viewHeight/2, 0, max(0, worldHeight - viewHeight))`。`worldToScreenY(worldY, cameraY) = worldY - cameraY`。
- 地面に立っているときは、プレイヤー中心がカメラの下限を超える位置にあるため、カメラは下端に張り付き、地面は画面の下から 80 の位置(従来と同じ)に見える。平地でのジャンプ(高さ約 140)では画面が上下に揺れない。
- 足場の上でのジャンプでは、プレイヤー中心に追従するため画面が上下に動く(スムージングや不感帯は設けない。気になれば後続で調整する)。

### 5. ステージ定義(`stage.ts`)と寸法
- `WORLD_WIDTH = 16800`、`WORLD_HEIGHT = 1620`(画面の 3 倍)、`GROUND_Y = WORLD_HEIGHT - 80 = 1540`、`SEA_X = WORLD_WIDTH - 240 = 16560`、`FALL_Y = WORLD_HEIGHT + 60`。
- 歩くだけの所要時間: `(SEA_X - 開始位置 100) / 280 ≈ 58.8` 秒(50〜70 秒の範囲)。
- ステージは、ヘルパー(`groundRun(x0, x1)`、`pit(x, w)`、`cliff(x, w, rise)`、`island(x, w, rise)`)で組み立て、各区間が「経路(立つ位置の列)」も返す。`STAGE = { world: WorldBounds, route: RouteNode[] }`。
- 区間の構成(目安。最終の数値は `stage.ts` に定義し、制約のテストで守る):

| 区間(x) | 内容 |
|---|---|
| 0〜2400 | 平地(スタート、ボスの闘技場。ボスは従来の位置 1600〜2000) |
| 2400〜4200 | 崖の階段(高さ 90 ずつ 3 段で上り、降りる)と浮島 |
| 4200〜6000 | 連続する穴(幅 120・150・180)。間に 200 の地面、上に浮島 |
| 6000〜8600 | 浮島の塔(高さ差 100〜110 で 8 枚、約 900 登る)→ 高所の足場から降りる |
| 8600〜11000 | 高さ 500〜800 の浮島の回廊(下に地面があり、落ちても戻れる) |
| 11000〜13400 | 崖の階段(5 段)と尾根、穴 |
| 13400〜15560 | 崖・浮島・穴の混合区間 |
| 15560〜16800 | 平地(海の手前 1000 の砂浜、16560 から海) |

- 制約(定数): 穴の幅 `MAX_PIT_WIDTH = 180`、上りの高さ差 `MAX_RISE = 110`、高さ差が `HIGH_RISE = 60` を超える足場への水平の隙間 `MAX_GAP_HIGH = 120`、頭上の空間 `HEADROOM = 100`。これらは、ジャンプの性能(初速 750、重力 2000 から、高さ約 140、空中時間約 0.75 秒、水平約 210)に余裕を見て決めた値。
- 描画の都合で、ボスの闘技場・砂浜は平地とする(ボス・部品の床が `groundY` であるため)。

### 6. 到達可能性の検証
- **構造の検査**(`validateStage`): 穴の幅、上りの高さ差、足場の隙間、頭上の空間、ステージの範囲内、平地の区間(スタート・闘技場・砂浜)に穴・崖・浮島がないこと、地形の 3 種類が含まれること、最高の足場の高さ。
- **経路のシミュレーション**: 経路の隣り合う足場 A → B について、実際の `stepPlayer` で、助走位置と跳び出しのタイミング(数十通り)を探索し、一定の時間内に B の上に立てる入力の組み合わせがあることを確認する。下りは、端から歩いて落ちれば到達できる。探索で見つからなければ、そのステージ定義を調整する。
- 手動プレイでの通しは、ブラウザでの確認と、利用者の確認で補う。

### 7. 描画(`renderer.ts`)
- すべてのワールド座標の描画を `y - cameraY` の画面座標で行う(横はこれまでどおり)。`draw` は `cameraX` に加えて `cameraY` を受け取る。
- 地面: 区間ごとに、従来の地面の色・草の帯(素材があれば画像のタイル)で描く。穴は地面を描かず、背景のまま(落下の様子が見える)。海は従来どおり `SEA_X` から右。
- 崖: 茶色の矩形(上面に草の帯)。浮島: 薄い緑の帯の矩形(厚み 20)。いずれも図形。
- 背景は縦には動かさない(画面全体を覆う)。HUD・タイトル・オーバーレイは画面座標のまま。

### 8. 既存コード・テストへの影響
- `config.ts` の `WORLD_WIDTH` / `GROUND_Y` / `SEA_X` の値が変わる。これらを import しているテストは追従する。数値を直接書いているテストは、実装時に調整する。
- `createPlayer` / `stepPlayer` / `stepGame` / `createGame` の引数(`world`)は維持し、`WorldBounds` の追加項目は省略可能にする。
- 既定の世界(`DEFAULT_WORLD`)は、新しいステージにする。平地を前提とする既存テスト(ボス・拾得・脱出)は、闘技場と砂浜が平地であることで、そのまま通る見込み。

## Risks / Trade-offs

- [数値の実装が多く、ステージの手書きに誤りが出やすい] → 構造の検査と経路のシミュレーションを Vitest で必須にし、ステージ定義の変更のたびに自動で検出する。
- [経路のシミュレーションが、実際のプレイ(人間の操作)より楽観的/悲観的] → 探索する入力は「一定方向に押し続けて 1 回ジャンプ」に限り、人間でも再現できる範囲にする。最終的な遊びやすさは、手動プレイで確認・調整する。
- [足場の上のジャンプで画面が上下に揺れる] → 現段階では許容(仕様は「プレイヤーが画面の中央」)。気になれば、不感帯やスムージングを後続の change で入れる。
- [復帰位置の記録が、足場の縁で穴のすぐ近くになり、続けて落ちる] → 「足元の幅全体が支えられている」位置だけを記録し、復帰後の無敵と、押し戻しがない分の猶予を与える。
- [浮島から降りる操作がなく、降りたいときも端まで歩く必要がある] → 仕様の範囲外として許容(proposal に明記)。
- [ステージの長さが約 3 分に届かない] → 敵と部品を置く次の change で調整する前提で、歩くだけの時間(約 59 秒)と構造を先に確定する。

## Open Questions

- 各区間の最終的な数値(段差・間隔・位置)、落下速度の上限(1500 px/s)、頭上の空間(100)は、実装時の検証と手動プレイで調整する(spec の要件の範囲内)。
