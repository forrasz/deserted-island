# Proposal

## Why

脱出条件である「イカダの部品を集める」を成立させるには、プレイヤーが入手手段を持つ必要がある。
本ゲームでは部品を敵ボスのドロップとして入手させる。そこで、倒せるボスと、ドロップしたアイテムを拾って所持する仕組みを最小構成で作り、アイテム収集の基盤を確立する。

## What Changes

- ボス「カクレモモジリ」(こびとづかん)を1体、ワールド上に配置する。見た目は図形によるプレースホルダーとする
- ボスは決まった範囲を左右に往復する。プレイヤーが上から踏みつけるとダメージを受け、複数回の踏みつけで倒せる
- 踏みつけ成功時、プレイヤーは上方向に跳ね返る。ボスは被弾直後の短い無敵時間を持ち、1回の踏みつけで複数回ダメージを受けない
- ボスの側面・下からの接触では、プレイヤーはダメージを受けず、横方向へ押し戻される(HP・ゲームオーバーは扱わない)
- ボスを倒すと、その位置にイカダの部品(1種類)がドロップし、地面に落ちて留まる
- プレイヤーが部品に触れると拾得され、所持数が増える。所持数を画面上(HUD)に表示する
- ゲームロジック(ボス行動・踏みつけ判定・ドロップ・拾得・所持)は `src/core` の純粋な TypeScript とし、Vitest でテストする
- **含めないもの**: ボスの複数体化・部品の複数種、プレイヤーのHP/ゲームオーバー、イカダの完成条件・脱出(クリア)、サウンド、画像アセット、ボス戦専用のアリーナや演出

## Capabilities

### New Capabilities
- `boss-enemy`: ボスの配置、往復移動、踏みつけによる被ダメージと撃破、被弾後の無敵時間、側面・下からの接触時の押し戻し
- `raft-part-collection`: ボス撃破時のイカダ部品のドロップ、拾得、所持数の管理と HUD 表示

## Impact

- 新規コード: `src/core/` にボス・部品・所持状態・当たり判定のロジックとテスト、`src/platform/renderer.ts` にボス・部品・HUD の描画、`src/main.ts` に更新順序の接続
- 既存 spec への影響なし。`player-movement` の「ジャンプ」要件(二重ジャンプ禁止)とは別に、踏みつけ成功時の跳ね返りは `boss-enemy` 側で定義する
- 新規依存関係: なし
- 前提(確認事項): 「こびとづかん」の既存キャラクターの設定は仕様に取り込まず、名前と「ボスである」点のみを使う。見た目・挙動は本ゲーム独自のプレースホルダーとする
