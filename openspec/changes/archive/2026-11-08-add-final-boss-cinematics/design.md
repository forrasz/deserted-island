# Design

## Context

- `GameState` は、ボス・敵・弾・柱・プレイヤー・HP・ボーナス・無敵モードなどを持つ。`stepGame(state, input, dt, world)` が、ボーナス中は `stepBonus` へ切り替え、通常は プレイヤー → ボス(`stepBossScript`)・敵・弾 → 接触 → ドロップ → 柱 → 海・脱出、の順で更新する。ボスは、プレイヤーが遠くにいても、ゲーム開始から動く(ヌシも、遠くで突進して柱を壊し続けている)
- 画面遷移は `flow.ts`(`title` / `playing` / `cleared` / `gameover`)。`playing` の中で `game.escaped` になると `cleared`、`game.dead` になると `gameover`。`cheat`(隠しコマンドの進み具合)も持つ
- ボスは、体力が 0 になると `damageBoss` が `alive: false` にし、その更新で、部品のドロップと柱の崩壊が起きる
- カメラは `cameraOf(game)`(`camera.ts`)が、プレイヤー(ボーナス中は広間)の位置から決め、`main.ts` が `Renderer.draw(flow, cameraX, cameraY)` へ渡す。描画は、図形と文字だけ
- 演出の素材も、効果音もない。画面の動き(暗転・揺れ・フラッシュ)と、図形で表す

## Goals / Non-Goals

**Goals:**
- 登場・撃破・エンディングの「時間割」と「状態の遷移」を、純粋関数・純粋な状態として `src/core` に置き、Vitest で確認する
- 既存の仕組みに、小さな状態を足すだけで、演出を差し込む(`stepGame` の大きな書き換えはしない)
- 演出中に、プレイヤーが理不尽な被弾や詰みにならない

**Non-Goals:**
- 効果音・BGM・画像素材、通常ボスの演出、ボスの体力バー、スキップ(proposal 参照)

## Decisions

### 1. ヌシの登場は `GameState.intro` の 3 状態で表す
`intro: { state: 'sleeping' | 'playing' | 'done'; t: number }`。初期は `sleeping`。
- `sleeping`: ヌシ(`kind === 'nushi'`)は `stepBossScript` を呼ばず、動かない(踏みつけ・接触の判定は従来どおり)。プレイヤーの右辺が `西の柱の左辺 - 360`(`INTRO_TRIGGER_DISTANCE`)以上になり、ヌシが生きていれば、`playing` へ(`t = 0`)
- `playing`: `stepGame` は、世界を進めず(ボーナスと同じく、早期 return)、`t += dt` だけ行う。入力も使わない。`t >= INTRO_TIME(3.0)` で `done` にし、ヌシは行動の最初から始まる
- `done`: 通常どおり
- 理由: ボーナスで使った「サブ状態で、早期 return」の形を使い回せる。`Flow` を変えずに済み、演出中もフェーズは `playing` のまま(クリア・ゲームオーバーの判定を壊さない)
- 代替: `Flow` にフェーズを足す。演出中のカメラ・描画は `GameState` の値で決めたいので、`GameState` に持たせる
- ヌシを眠らせるのは、ヌシだけ(他のボスの「遠くでも動く」は、今回は直さない)

### 2. 撃破演出は `Boss.dying`(ゲーム内の残り秒)で表し、時間を 0.3 倍にする
- ヌシは、体力が 0 になっても `alive` のまま、`dying = NUSHI_DYING_TIME(1.05)`、`stagger = 0` にする(`damageBoss` が、`kind === 'nushi'` のときだけ)
- `stepBossScript`: `dying > 0` のとき、動かず・弾を出さず、`dying` を `dt` ずつ減らす。0 以下になったら、`alive: false`(既存の「alive が true → false になった更新」で、部品のドロップと柱の崩壊が起きる)
- `bossFlags` に `dying` を足し、`harmless`(踏んでもダメージがなく、触れても被弾しない)として扱う
- `stepGame` は、冒頭で、`dying > 0` のボスがいれば、`dt` に `DYING_TIME_SCALE(0.3)` をかける。1.05 ゲーム秒 ÷ 0.3 = 3.5 実秒。プレイヤー・弾・無敵時間なども、同じ倍率で遅くなる
- `dying` が始まった更新で、弾と衝撃波をすべて消す(spec「演出中は安全」)
- 理由: 既存の「撃破された更新で部品を落とす」を変えず、撃破を遅らせるだけで済む。時間の倍率を `dt` に入れるので、物理やタイマーが、同じ割合で遅くなる(個別の分岐がいらない)
- 代替: `Flow` で `stepGame` へ渡す `dt` を変える。ゲームの純粋な更新の外に、時間の知識が出るので、`stepGame` の中に置く

### 3. エンディングは `Flow.phase = 'ending'` とし、経過時間を `Flow.ending` で持つ
- `stepFlow`: `playing` で `game.escaped` になったら、`phase: 'ending'`・`ending: 0`。`ending` の間は、入力・隠しコマンドを無視し(`pressed` による遷移もしない)、`ending += dt`。`ending >= ENDING_DURATION(12)` で `cleared` へ
- `cleared` の画面は、従来どおり(「脱出成功!」)。再プレイは `createGame()` なので、`intro` も `ending` も初期に戻る
- 世界は進めない(`stepGame` を呼ばない)。タッチ操作の決定のタップは、`phase !== 'playing'` で有効になるが、`ending` では無視される(`stepFlow` が使わない)

### 4. 演出の時間割は、純粋関数にまとめる(`src/core/cinematic.ts`)
描画側(`renderer.ts`)は、時刻を渡して、値を受け取って描くだけにする。
- `introTimeline(t)`: `{ dark: 0〜0.6, warning: boolean, nameAlpha: 0〜1, shake: px }`。`dark` は、0.5 秒で 0.6 まで増え、最後の 0.5 秒で 0 に戻る。`warning` は 0.34 秒周期(1 秒に約 3 回)で点滅。`nameAlpha` は 1.0 秒から 1.5 秒で 1 になり、最後の 0.5 秒で 0。`shake` は、0〜1.0 秒が 6 px、その後 3 px、最後の 0.3 秒で 0。揺れは `sin` の合成(乱数なし)
- `introCameraBlend(t)`: プレイヤーのカメラ → ヌシのカメラ の補間(0〜0.8 秒で 0 → 1、2.5 秒以降で 1 → 0。イージング)。`cameraOf` が、これで 2 つのカメラ位置を混ぜる
- `dyingProgress(dying)`: 進行度 `p = 1 - dying / NUSHI_DYING_TIME`(0〜1)
- `explosions(p)`: 進行度 p までに起きた爆発の一覧 `{ x, y, r, alpha }`(ヌシの矩形に対する相対位置 0〜1・半径・濃さ)。i 番目は `p >= i * 0.06` で始まり、0.25 の長さで広がって消える。位置は、i から決める決定的な値(`sin` のハッシュ)
- `dyingFlash(p)`: 白いフラッシュの濃さ。`p` が 0.7 → 0.92 で 0 → 0.85、0.92 → 1.0 で 0.85 → 0(最大 0.85。点滅ではなく、1 回の山)
- `dyingBossVisible(p)`: `p < 0.92`(フラッシュの頂点で、ヌシが消える)。`dyingShake(p)`: 揺れの大きさ
- `endingScene(t)`: `{ sunY, raftX, raftY, raftScale, islandX, islandScale, birds[], messages: { text, alpha }[], wave: number }`。夕日は 0 → 12 秒で、水平線へ向かって下がる(地平線の少し上まで)。イカダは、画面の手前(大きさ 1)から、水平線の方へ(大きさ 0.25)へ移る。島は、左へ遠ざかって縮む。メッセージは、1 つ目(1.5〜5.5 秒)、2 つ目(6.0〜9.0 秒)、3 つ目(9.5〜12 秒)が、ゆっくりフェードイン・アウト
- 理由: 時刻 → 値の関数は、純粋でテストしやすい。見た目(色・形)の調整は、描画側だけで済む

### 5. カメラ
`cameraOf(game)` で、`game.intro.state === 'playing'` のとき、`introCameraBlend(intro.t)` で、プレイヤーのカメラとヌシのカメラ(`computeCameraX(ヌシの中心)`)を線形に混ぜる。縦は、本編のステージの高さで、同様に混ぜる。

### 6. 描画
- 登場演出: 本編を描いたあと、画面全体を黒の半透明で暗くし(`dark`)、中央上に赤い「WARNING」(`warning` が true の間)、中央に「ヌシ」の名前(`nameAlpha`)。画面の揺れは、描画全体を `ctx.translate` でずらす(HUD も一緒に揺らす)
- 撃破演出: ヌシの体を白と元の色で交互に(約 0.1 秒周期)描き、`explosions` を、広がる円(黄 → 橙 → 赤)で描く。`dyingFlash` を、画面全体の白い矩形で重ねる。`dyingBossVisible` が false のとき、ヌシは描かない。揺れは `dyingShake`
- エンディング: 本編を描かず、`endingScene` で、空のグラデーション(橙 → 紫)、水平線、夕日(円と光の筋)、海(波の線の動き)、遠ざかる島(シルエット)、イカダとプレイヤー(図形)、鳥(小さな V 字)、メッセージを描く。終わりに、画面が静かに暗くなって(最後の 0.5 秒)、クリア画面へ
- 光過敏への配慮: 全画面の点滅は 1 秒に 3 回まで。白の最大の濃さは 0.85

### 7. 既存の仕組みとの関係
- ボーナスの入場・無敵モード・隠しコマンド: `intro.state === 'playing'` の間は、`stepGame` が早期 return なので、ボーナスへは入らない。無敵モードのコマンドは、`Flow` が受け付けるので、演出中も入力できる(影響なし)。`ending` では受け付けない
- 柱: ヌシが眠っている間は、突進が起きないので、柱は壊れない
- 既存テスト: ゲーム内でヌシを動かす/倒すテストは、`intro` を `done` にした状態から始め、撃破は `dying` の完了まで進める。脱出のテストは、`ending` を経る

## Risks / Trade-offs

- **演出中の操作不能**: 登場が 3 秒、エンディングが 12 秒で、スキップできない(エンディングは仕様どおり)。登場演出は、1 回のプレイで 1 回だけにして、再挑戦(ゲームオーバー後)でも、プレイをやり直すので、また見ることになる。長ければ、将来スキップを足す(今回は含めない)
- **スローモーションの副作用**: 時間が 0.3 倍なので、撃破演出中のプレイヤーの動きも遅くなる。ヌシの弾は消し、ヌシは無害なので、害はない。ほかの敵がいる場合も、同じ倍率で遅くなる
- **ヌシだけを眠らせる**: ほかのボスの「遠くでも動く」は直さない(別の change)。ヌシは、画面に入る前から眠っているので、柱が勝手に壊れることもなくなる
- **登場の発動位置**: 西の柱の手前 360 px。柱の手前には広い平地があるので、近づいて見える位置で発動する。画面(幅 960)の中に、柱とヌシが入る手前で止まる
- **演出の見た目の好み**: 色・速さ・メッセージの文言は、実際に見て調整する(数値は `cinematic.ts` にまとめ、変えたら spec も更新する)
