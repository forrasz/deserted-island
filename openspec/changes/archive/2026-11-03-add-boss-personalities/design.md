# Design

## Context

- 現状: `Boss`(`boss.ts`)は、往復(`stepBoss`)と、踏まれたときの体力の減少(`damageBoss`)だけを持つ。大きさは固定値(`BOSS_WIDTH` 80、`BOSS_HEIGHT` 100)で、`bossRect`・ドロップ位置・押し戻し・描画・配置の検査がこの固定値を参照している。`GameState` は `bosses`(10 体)と `enemies`(ザコ敵)を持ち、`stepGame` が各体を更新して衝突を解決する。
- 動機とスコープは proposal.md、要件は specs(`boss-behaviors` / `projectiles` / `final-boss`、変更する `boss-enemy`)を参照。
- 方針: ロジックは `src/core`(DOM/Canvas 非依存、Vitest でテスト)、描画は `src/platform`。演出(画面の揺れ・火花・バナー・体力バー)は次の change「④b」で扱う。

## Goals / Non-Goals

**Goals:**
- ボスの個性を「行動の流れ(データ)+ 1 つの更新関数」で表し、決定的(乱数なし)でテストしやすくする
- 弾・衝撃波の仕組みを作り、ボス 9 体と最終ボスの攻撃に使う
- 最終ボスの大きさ・形態変化を、ボスの大きさの一般化(`w`・`h`)で実現する
- 既存のボスのテストを大きく壊さない(既定の行動は「往復だけ」)

**Non-Goals:**
- 演出全般、体力バー(画面上部)、効果音・BGM、画像素材
- ザコ敵の追加、プレイヤーの新しい操作

## Decisions

### 1. ボスの定義の拡張(`boss.ts`)
```ts
type BossKind = 'momojiri' | 'tobihane' | 'oogui' | 'tamafuki' | 'naminori'
              | 'futago' | 'ukiuki' | 'kororin' | 'jishin' | 'nushi';

interface BossDef {
  id: number; kind: BossKind; name: string;
  maxHp: number; speed: number; rangeWidth: number;
  w: number; h: number;       // 大きさ(通常 80×100、ヌシ 200×250)
  color: string;              // 図形で描くときの色
}
```
- `BOSS_DEFS` は 10 件(id 0〜9)。体力は `[3,3,3,4,4,4,4,5,5,12]`、速さは従来どおり `80〜140`、往復範囲の幅は `[400,410,…,490,600]`。
- `Boss` に `w`・`h`・`kind`・`name` を持たせ、`bossRect` は `w`・`h` を使う。`createBoss(…, def)` は既定の定義(従来の 1 体、80×100)を持ち、既存テストの呼び出しはそのまま動く。
- `BOSS_WIDTH` / `BOSS_HEIGHT` は、通常ボスの大きさの定数として残す(最終ボスだけ別)。固定値を直接使っている箇所(`game.ts` の中心位置・ドロップ位置・押し戻し、`stage-check.ts`、`renderer.ts`)は、ボスごとの `w`・`h` に置き換える。

### 2. 行動の流れ(`boss-scripts.ts`):データ + 1 つの更新関数
```ts
type BossStep =
  | { a: 'patrol'; time: number; speed?: number }          // 往復(速さの既定はボスの speed)
  | { a: 'burrow'; time: number }                          // もぐる(触れない・踏めない)
  | { a: 'telegraph'; time: number }                       // 予備動作(静止・点滅)
  | { a: 'dash'; time: number; speed: number }             // プレイヤーの方向へ突進(予備動作の終わりの向き)
  | { a: 'rest'; time: number }                            // 休み(踏める)
  | { a: 'jump'; vy: number; air?: number; wave?: number } // ジャンプ。air = 空中の水平の速さ(プレイヤー方向)、wave = 着地で出す衝撃波の速さ
  | { a: 'shot'; speed: number; tops: number[] }           // 直進弾(高さごとに 1 発)。即時
  | { a: 'lob'; vx: number; vy: number }                   // 左右へ放物線の弾。即時
  | { a: 'wave'; speed: number }                           // 左右へ衝撃波。即時
  | { a: 'rise'; height: number; speed: number }           // 浮上
  | { a: 'hover'; time: number; speed: number }            // 空中で往復
  | { a: 'aim'; time: number; speed: number }              // プレイヤーの真上へ水平に動く
  | { a: 'drop'; speed: number }                           // 急降下(着地で終わる)
  | { a: 'dizzy'; time: number }                           // 目を回す(踏める)
  | { a: 'roll'; time: number; speed: number }             // 転がる(踏めない)
  | { a: 'transform'; time: number };                      // 変身(安全)
```
- `BOSS_SCRIPTS: Record<BossKind, BossStep[]>`(最終ボスは形態 1・2 の 2 本)。各ボスの流れは次のとおり(数値は specs のとおり):

| ボス | 流れ |
|---|---|
| カクレモモジリ | 往復 2.5 秒 → もぐる 1.2 秒 |
| トビハネ | 往復 1.0 秒 → ジャンプ(vy 800、空中でプレイヤー方向へ 160) |
| オオグイ | 往復 2.0 秒 → 予備動作 0.6 秒 → 突進 0.8 秒(320) → 休み 0.8 秒 |
| タマフキ | 往復 1.6 秒 → 予備動作 0.4 秒 → 直進弾 1 発(260) |
| ナミノリ | 往復 1.2 秒 → ジャンプ(vy 700、着地で衝撃波 280)→ 休み 0.6 秒 |
| フタゴ | 往復 1.4 秒 → 予備動作 0.4 秒 → 放物線の弾 2 発(左右、vx 300、vy 650) |
| ウキウキ | 浮上(150、毎秒 200)→ 浮遊往復 2.0 秒(120)→ 狙う 1.0 秒(200)→ 予備動作 0.5 秒 → 急降下(800)→ 目を回す 1.2 秒 |
| コロリン | 往復 1.5 秒 → 転がる 2.0 秒(260)→ 目を回す 1.2 秒 |
| ジシン | 往復 1.5 秒 → 予備動作 0.5 秒 → 衝撃波(360)→ 0.4 秒待つ → 衝撃波(360)→ 休み 0.8 秒 |
| ヌシ(形態 1) | 往復 1.2 秒(100)→ 予備動作 0.8 秒 → 突進 1.0 秒(400)→ 休み 1.0 秒 → 予備動作 0.5 秒 → 直進弾 3 発 → ジャンプ(vy 800、着地で衝撃波 300)→ 休み 1.2 秒 |
| ヌシ(形態 2) | 形態 1 の時間を 0.6 倍、突進を 2 回、直進弾 5 発、衝撃波を 0.5 秒おきに 2 回 |

- `Boss` に `step`(現在の行動の番号)・`t`(その行動の経過時間)・`form`(1 または 2)・`aimDir`(突進の向き)を持たせる。`stepBossScript(boss, ctx, dt)` が、現在の行動を 1 更新分進め、時間が尽きたら次の行動へ進む(最後の次は最初に戻る)。即時の行動(`shot`・`lob`・`wave`)は、その更新で弾を生み、すぐ次へ進む。`jump`・`drop` は着地で、`rise` は高さに達したときに次へ進む。
- 戻り値は `{ boss, spawns: Projectile[] }`。既存の `stepBoss(boss, dt)`(戻り値は `Boss`)は、行動が「往復だけ」の既定のボスの更新として残し、既存テストはそのまま通る。
- 状態の目印は、現在の行動から導く関数 `bossState(boss)` にまとめる: `hidden`(burrow)、`stompImmune`(roll)、`harmless`(transform)、`telegraph`(telegraph の間)。

### 3. 弾と衝撃波(`projectile.ts`)
```ts
interface Projectile { id: number; kind: 'shot' | 'arc' | 'wave'; x: number; y: number; w: number; h: number;
                       vx: number; vy: number; life: number; alive: boolean; }
```
- 大きさ: 直進弾・放物線の弾は 24×24、衝撃波は 32×24(地面の上に立つ)。寿命: 直進弾 3 秒・衝撃波 2 秒(放物線の弾は地面に達したら消える)。
- `stepProjectile(p, dt, world)`: 直進弾・衝撃波は `x += vx·dt`、放物線の弾は重力(`GRAVITY`)で `vy` を増やす。寿命・ステージの外・地面への到達で `alive = false`。
- 弾の高さ(直進弾の上端 y、地面からの高さ): 低 48・中 72〜100・高 134〜170 など、段階を変える。地面に立つプレイヤー(高さ 56)に当たるのは低い弾(48)と、わずかに重なる 72 まで。ジャンプで飛び越えられる。
- 弾との接触(`resolveProjectileContact`): プレイヤーと重なったら、無敵でなければ被弾(HP -1・跳ね上がり・2 秒の無敵)にして、その弾を消す。無敵中は消さず、通り抜ける。ザコ敵と同じ被弾の扱いに合流させる(`hit` は 1 更新に 1 回)。
- `GameState.projectiles` を持ち、再プレイで空にする。

### 4. 接触の扱い(`game.ts`)
- ボスとの衝突(`resolveBossContact`)は、`bossState` の目印で分岐する。
  - `hidden`: 接触なし(押し戻しも被弾も踏みつけもない)。
  - `stompImmune`(転がり): 踏みつけにしない(通常の接触として押し戻し + 被弾)。
  - `harmless`(変身): 踏みつけは跳ね返りだけでダメージなし。それ以外の接触では被弾も押し戻しもしない。
- 最終ボスなど大型のボスは、`w`・`h` を使って、中心位置・押し戻し・ドロップ位置・踏みつけの上辺を計算する。
- ボスの更新で出た弾(`spawns`)を、その更新の末尾で `projectiles` に加える。更新の順序: プレイヤー → ボス(行動 → 弾の生成)→ ザコ敵 → 弾の更新 → 衝突(ボス → ザコ敵 → 弾)→ ドロップ → 部品 → 拾得 → 脱出。被弾は 1 更新に 1 回。

### 5. 最終ボス「ヌシ」の形態変化
- 体力が `maxHp / 2`(6)以下になった更新の次に、`transform` の行動(1.5 秒)へ割り込み、終わったら `form = 2` にして強化形態の流れの先頭から始める。`form` が 2 になったあとは割り込まない(1 回だけ)。変身中は踏んでも体力が減らない(`harmless`)。
- 強化形態は、形態 1 の流れを `scaleScript(script, 0.6)` で時間だけ縮めたものに、突進の追加・弾の増加・衝撃波の連続を加えて作る。

- **休みの間のかがみ(最終ボスだけ)**: ヌシの高さ 250 は、プレイヤーのジャンプの最高点(約 140)より高く、地面からのジャンプでは踏めない。そのため、`BossDef.restH`(100)を持たせ、`rest` の間だけ、当たり判定の高さを `restH` に下げる(下辺は地面のまま)。`bossRect` と `bossFlags().crouch` がこれを表し、踏みつけの上辺・ドロップ位置・描画は `bossRect` を使う。休み以外では高さ 250。(実装中に、ユニットテストが「プレイヤーを上空に置く」形で見逃していた問題を見つけ、追加した。)

### 6. ステージ(`stage.ts`、`stage-check.ts`)
- `BOSS_LEFTS` は据え置き。ヌシの往復範囲の幅は 600(`[23810, 24410]`)で、大きさ 200 を含めても `SEA_X - 600 = 24960` 以内に収まる。
- 配置の検査(ボスの前後 100 が平地、安全な区間、ボスどうしが重ならない、ザコ敵がボスの範囲と重ならない)は、`BOSS_WIDTH` の固定値ではなく、ボスごとの幅(`def.w`)を使う。

### 7. 描画(`renderer.ts`)
- ボスは、種類ごとの色の矩形を、ボスごとの `w`・`h` で描く(素材があれば従来どおり画像)。予備動作の間は、白と元の色で点滅させる。`hidden`(もぐり)は描かない(地面に小さな盛り上がりを描いてもよい)。転がり中は丸みのある図形(円)で描く。
- 弾は黄色の円、放物線の弾はオレンジの円、衝撃波は赤い三角(または帯)で描く。画面外は描かない。

## Risks / Trade-offs

- [ボスの更新の戻り値が増えて、既存テストの修正が多い] → 既存の `stepBoss` を残し、既定の行動を「往復だけ」にする。新しい更新は `stepBossScript` に分ける。
- [ボスの大きさを固定値から外すと、取りこぼしが出る] → `BOSS_WIDTH`・`BOSS_HEIGHT` の参照箇所を洗い出し、型チェックとテストで確認する(grep で残りがないことも確認する)。
- [弾が多く、避けにくい/当たりすぎる] → 弾の速さ・高さ・間隔は `config.ts` と `boss-scripts.ts` に集約し、遊んで調整する。予備動作で、見てからよけられるようにする。
- [ウキウキが空中にいる間は踏めない] → 目を回している間だけ踏めるのが個性。手が届かないことを、スクリプトのテストと、ブラウザでの確認で保証する(降下・着地・目を回す時間が、仕様どおり)。
- [ヌシの体力 12 は、踏みつけに 0.5 秒の無敵があるため、戦いが長い] → 休みの間に確実に踏める設計(0.6〜0.8 秒の休み)で、長くなりすぎないよう、ブラウザの通しで確認して調整する。
- [「こびとづかん」の既存キャラクター] → 名前・行動はすべて独自の設計。初期のボス名「カクレモモジリ」のみ、1 体目に残す。

## Open Questions

- 各ボスの時間・速さ・弾の高さ・衝撃波の速さの最終値は、実装と手動プレイで調整する(spec の数値は仮置きで、変更する場合は spec も合わせて更新する)。
- 次の change「④b 演出」で、登場演出・被弾と撃破の演出・最終ボスの専用演出・体力バーを扱う。
