# Design

## Context

- プレイヤーの描画は、`Renderer.drawPlayer`(通常の画面とボーナスの広間で共用)が、素材 `player`(1 枚絵)があれば `fitToBox` で矩形に合わせて描き、なければ赤い四角で描く。無敵中は `blinkVisible(hitInvuln)` で点滅し、無敵モードでは、画像のとき金色の枠を描く。向きは `nextFacing(prev, vx)`
- 素材の読み込みは、`src/core/assets.ts`(キーとファイル名)と `src/platform/assets.ts`(`loadAssets`。成功・失敗・5 秒の時間切れを待ち、失敗は null)。素材は `public/assets/<name>.png` だけ
- プレイヤーの状態: `Player { x, y, vx, vy, onGround, coyote?, jumpBuffer? }`、`GameState.hp / hitInvuln / dead`、ボーナスでは `BonusState.stun`。被弾した更新で、`hitInvuln` が `PLAYER_INVULN_TIME`(2 秒)になる
- ゲームの更新は固定タイムステップ(1/60)で、描画は `requestAnimationFrame` ごと。ゲームオーバーでは、世界は進まない(`stepFlow` が `stepGame` を呼ばない)
- 素材: `public/images/player.jpeg`(1376×768 の JPEG、アルファなし)。背景は、灰色 2 色(RGB 約 144 と 192 の無彩色)の市松模様で、画像に焼き込まれている。事前の調査(使い捨ての確認)では、画像の外側から、無彩色で明るい(R > 150)画素の連結成分だけを背景にすると、背景が全体の約 69 % で、前景の連結成分が 77 個(面積 3000 以上の大きいものが 42 個 = コマ、残りは砂ぼこり・星・文字)に分かれた。コマの外接矩形の大きさは、幅 66〜144・高さ 71〜195

## Goals / Non-Goals

**Goals:**
- 状態に合わせて動く、スプライトシートのプレイヤーを、少ない変更で足す
- 動きの選択を、純粋な関数(`src/core`)にして、Vitest で確認する
- シートが使えなくても、ゲームは変わらず動く(従来の描画へのフォールバック)
- 下ごしらえを、再現できるツールにする

**Non-Goals:**
- プレイヤー以外のアニメーション、画像の新規作成・修正、ジャンプ・移動の仕様変更、効果音(proposal 参照)

## Decisions

### 1. 素材は「シート PNG + コマの一覧 JSON」にして、既存の 7 素材とは別に読み込む
`public/assets/playersheet.png` と `playersheet.json`。既存の素材(`ASSET_KEYS` の 7 種)の仕組み(1 キー = 1 PNG)には混ぜず、`loadPlayerSheet(baseUrl, timeoutMs)` を別に用意する(`AssetStore` に `playerSheet` として載せる)。
- 理由: 1 キー = 1 枚の前提を崩さず、既存の仕様(`sprite-assets`)を変えずに済む。失敗時は、`playerSheet = null` で、従来の描画へフォールバック
- 一覧 JSON の形: `{ "version": 1, "referenceHeight": number, "clips": { "idle": Frame[], "walk": Frame[], "run": Frame[], "jump": Frame[], "landStill": Frame[], "landRun": Frame[], "hit": Frame[], "knockout": Frame[] } }`、`Frame = { x, y, w, h, fx, fy }`(`x, y, w, h` はシート上の矩形、`fx, fy` は矩形内の足元の位置(足の中心の x と、足の下端の y))。`referenceHeight` は、待機のコマの高さ(倍率の基準)
- 検証関数 `validateAtlas(json, sheetWidth, sheetHeight)`: コマ数・矩形がシートの中・足元が矩形の中・値が数であること。不正なら、フォールバック

### 2. 動きの選択は、純粋な状態機械にする(`src/core/player-anim.ts`)
```
入力(毎描画): { onGround, vx, vy, hp/dead, hitInvuln, stunned } と dt
内部状態 AnimState: { clip, t(その動きの経過秒), airT(空中にいた秒), prevOnGround, prevHitInvuln, justTookOff(離陸からの秒), landKind }
出力: { clip, frame(0 起点), nextState }
```
- 規則は spec の優先順(やられ > 被弾 > 硬直 > 着地 > 空中 > 地上)。被弾の始まりは、`hitInvuln` が前の描画より増えたとき(`prevHitInvuln < hitInvuln`)で検出する。被弾の動きは 0.5 秒(4 コマのうち 3 コマを 約 0.17 秒ずつ)
- 離陸: `onGround` が true → false に変わった描画で `takeoffT = 0`。着地: false → true で、`airT >= 0.2` なら着地の動きを始める(`vx` の絶対値が 120 未満なら `landStill`、以上なら `landRun`)。着地の動きは、時間で終わる(`landStill` は 4 コマ × 0.06 秒、`landRun` は 5 コマ × 0.05 秒)。着地中でも、ジャンプ・被弾・やられが来たら、そちらが優先
- コマの進め方: `待機` は 0.15 秒/コマ(ループ)、`歩く` は `clamp(0.12 * 150 / |vx|, 0.08, 0.2)`(ループ)、`走る` は 0.07 秒(ループ)。ループは `floor(t / period) % n`。1 回再生は、`min(floor(t / period), n - 1)`。やられは 0.35 秒/コマで、最後のコマを保つ
- 時間: アニメーションは、ゲームの状態ではなく、描画の経過時間(実時間)で進める。ゲームが止まっていても(ゲームオーバー)、やられのコマが進む。登場演出・エンディングの間は、ゲームの世界が止まっているので、`vx` などは変わらない(待機のまま)
- 理由: ゲームの状態(`Player`)を増やさずに、描画側で、速さ・接地・HPから、見た目を決められる。ゲームのロジック・テストを変えずに済む。状態機械は、入力と dt を与えれば、結果が決まるので、テストしやすい

### 3. 描画: 倍率は一定で、足元をそろえる
- 倍率 `scale = DISPLAY_HEIGHT(70) / referenceHeight`。すべてのコマに同じ倍率
- 描画位置: コマの足元(`fx, fy`)を、プレイヤーの矩形の下辺の中央(`x + 20, y + 56`)にそろえる。左向きは、水平に反転して、足元の x を中心にして描く(反転しても、足元がずれない)
- 無敵の点滅(`blinkVisible`)・無敵モードの金色の枠(コマの外接矩形に)は、既存の規則のまま
- ボーナスの広間・ゲームオーバーの背景でも、同じ関数で描く(`drawPlayer` を共通で使う。`GameState.dead` なら、やられの動き)
- 当たり判定(`playerRect`・`playerHurtRect`)は、変えない
- フォールバック(シートなし): 従来の `drawPlayer`(1 枚絵 → 赤い四角)のまま

### 4. 下ごしらえのツール(`tools/build-player-sheet.mjs`)
Chrome(puppeteer-core)の canvas で、画像を読み込んで処理する。リポジトリの依存関係には加えない(ツールの先頭に、実行方法を書く)。
1. **背景の透過**: 画像の縁から、無彩色(R・G・B の差が小さい)で明るい(R > 150)画素を、フラッドフィルで背景として、透明にする。縁の 1 画素(背景に接している前景の画素)で、無彩色で明るいものは、半透明にして、白い滲みを減らす
2. **コマの検出**: 前景の連結成分(8 近傍)を求め、面積が 3000 以上のものをコマの核とする。小さい成分(砂ぼこり・星・「Zz」・文字)は、色と位置で分ける: 文字(暗い無彩色で、見出しの位置にあるもの)は除き、それ以外は、最も近い核のコマに含める
3. **動きの割り当て**: コマの核を、シート上の領域(見出しの位置から決めた 8 つの矩形: 待機・歩く・走る・ジャンプ・着地 2 組・被弾・やられ)ごとに集め、左から右へ並べる。コマ数が spec と一致するかを検査する
4. **足元**: コマの前景の下端を足の下端、下から 8 %(靴の部分)の前景の重心の x を足の中心とする。砂ぼこりが下端を伸ばす場合は、砂ぼこりを除いた核の下端を使う
5. **出力**: 透明なシート PNG(全体を、元の大きさのまま、または、最大の高さが 150 px になる倍率で縮小して、ファイルを小さくする)と、一覧 JSON。確認用に、コマの枠を描いたプレビュー PNG(リポジトリには入れない)も作り、目視で確認して、必要なら一覧を直す
- 縮小: 表示は 70 px 程度なので、シートは、コマの最大の高さが約 150 px(約 2 倍で、高解像度の画面でもきれい)になるように縮小して、ファイルを小さくする。縮小の倍率は、`referenceHeight` に反映する

### 5. ファイルの置き場所
- `public/images/player.jpeg` は、そのまま配信されてしまう(約 0.9 MB)ので、`assets-src/player-sheet-source.jpeg` へ移す(配信されない)。`assets-src/README.md` に、由来と、下ごしらえの手順を書く
- `public/assets/README.md` に、`playersheet.png` と `playersheet.json` の仕様(作り方・動きの名前とコマ数・足元・向き)を追記する

## Risks / Trade-offs

- **透過の汚れ**: 縁に白っぽい滲みが残る可能性がある。砂ぼこりと星と「Zz」は、半透明で、市松の上に重なっているので、背景の判定で、色が欠けたり、灰色が残ったりしやすい。結果を、色の違う背景(濃い青と明るい緑)に重ねたプレビューで見て、汚れがひどければ、(a) その部分だけ、手作業でコマの矩形を狭くして除く、(b) 利用者に、透明な PNG での再作成を依頼する
- **コマの検出の誤り**: 隣のコマとつながる(砂ぼこりが接する)、文字が混ざる、などの可能性。コマ数の検査と、プレビューの目視で確認する
- **見た目の大きさ**: 70 px で、周囲(ザコ敵 40 px・ボス 100 px)と釣り合うかは、実際に見て調整する(`DISPLAY_HEIGHT` は定数にする)
- **ファイルサイズ**: 縮小したシートは、数百 KB の見込み。起動時の読み込みが遅くならないか確認する(5 秒の上限で失敗として扱われる)
- **アニメーションの時間**: 実時間で進めるので、タブを裏に回して戻ったときなどに、短時間で進んで見えることがある。見た目だけで、ゲームへの影響はない
- **向き**: スプライトが右向きであることを前提にする。実際の向きを、プレビューで確認する(左向きなら、反転の向きを逆にする設定を、一覧に持たせる)
- **画像の権利**: 利用者が確認する前提。公開リポジトリに画像が載るので、権利に注意するよう、README に書く
