# Proposal

## Why

プレイヤーは、いまは赤い四角で描かれている。利用者が、32 ビット風のキャラクターのスプライトシート(待機・歩く・走る・ジャンプ・着地・被弾・やられ、約 41 コマ)を用意したので、これをプレイヤーの見た目に使い、ゲームの状態(止まっている・歩く・走る・ジャンプ・着地・被弾・やられ)に合わせて動かす。

素材は、`public/images/player.jpeg`(1376×768 の JPEG)に置かれている。透明ではなく、背景の市松模様が画像に焼き込まれていて、コマも格子状に並んでいない。そのため、素材の下ごしらえ(背景の透過とコマの切り出し)も、この change の範囲に含める。

## What Changes

- **素材の下ごしらえ**: スプライトシートの背景(灰色の市松模様)を、画像の外側から、その 2 色に近い部分だけを透明にして、透明な PNG にする。コマは、連結成分から自動で見つけた外接矩形を、目視で確認・修正して、各コマの位置・足元の位置を記した一覧(JSON)にする。出力は、`public/assets/playersheet.png` と `public/assets/playersheet.json`。元の画像は、配信されない場所(`assets-src/`)へ移す。下ごしらえを再現できるツール(`tools/build-player-sheet.mjs`)をリポジトリに置く
- **プレイヤーのアニメーション**: 状態に応じて、次の動きを再生する。
  - 待機(6 コマ)・歩く(7 コマ)・走る(7 コマ): 地上の水平の速さで切り替える(止まっている・歩く・走る)。歩く・走るの速さに合わせてコマが進む
  - ジャンプ(5 コマ): 踏み切りのしゃがみ・上昇・頂点・下降を、上下の速さで切り替える
  - 着地(砂ぼこり付き。止まって着地する 4 コマと、速さを持って着地する 5 コマ): 空中に 0.2 秒以上いたあとの着地で、約 0.25 秒再生する
  - 被弾(4 コマ): 被弾した直後の約 0.5 秒。ボーナスの石で硬直している間は、目を回すコマを出す
  - やられ(4 コマ): HPが 0 になったとき。ひざをつく → 倒れる → 倒れて動かない → 眠る(最後のコマを保つ)
- **表示**: キャラクターは、見た目の高さ 70 px(これまでの当たり判定の矩形 56 px より少し大きい)で、足元を地面にそろえて描く。向きは、既存の左右反転の仕組みを使う。無敵中の点滅と、無敵モードの金色の枠は、そのまま使う。**当たり判定(見た目の矩形 40×56・被弾判定 28×46)は変えない**
- **フォールバック**: スプライトシートが読み込めない(ファイルがない・壊れている・一覧が不正・時間切れ)ときは、これまでの動き(1 枚絵の `player.png` があればそれ、なければ赤い四角)で描く。ゲームの進行は変わらない
- アニメーションの選択(どの動きの、どのコマか)は、`src/core` の純粋な TypeScript とし、Vitest でテストする。シートの読み込みと描画は `src/platform` に置く
- **含めないもの**:
  - ボス・ザコ敵・弾など、プレイヤー以外のアニメーション
  - 画像の新規作成・修正(素材は利用者が用意したものを使う。下ごしらえで汚れが出る場合は、利用者に、透明な PNG での再作成を依頼する)
  - 効果音、画面の演出の変更、ジャンプ・移動の仕様の変更
  - 画像の権利の確認(利用者が確認する前提)

## Capabilities

### New Capabilities
- `player-animation`: スプライトシートとコマの一覧の定義、読み込みとフォールバック、状態からの動き・コマの選択、コマの進め方、表示(大きさ・足元・向き・点滅)

### Modified Capabilities
- `sprite-rendering`: 「当たり判定の矩形への合わせ方」に、プレイヤーのアニメーションのコマだけは、`player-animation` の定める高さ(70 px)で描くことを加える

## Impact

- 新規ファイル:
  - `public/assets/playersheet.png`・`public/assets/playersheet.json`(下ごしらえの出力)
  - `assets-src/player-sheet-source.jpeg`(元の画像。`public/images/player.jpeg` から移動)
  - `tools/build-player-sheet.mjs`(下ごしらえのツール。Chrome と `puppeteer-core` が別に必要。リポジトリの依存関係には加えない)
  - `src/core/player-anim.ts`(動きとコマの選択)・テスト
- 変更するコード:
  - `src/platform/assets.ts`・`src/core/assets.ts`: スプライトシートと一覧の読み込み(既存の 7 素材とは別に、失敗してもゲームを止めない)
  - `src/platform/renderer.ts`: プレイヤーの描画を、コマに切り替える(通常の画面・ボーナスの広間・ゲームオーバー)
  - `src/main.ts`: 描画に、時間の経過とプレイヤーの状態を渡す(必要なら)
  - `public/assets/README.md`・`README.md`
- 既存テストへの影響: 当たり判定・ゲームの状態は変わらないので、ほぼなし
- 新規依存関係: なし(ツールの実行に、手元で puppeteer-core と Chrome を使うが、プロジェクトの依存には含めない)
- 前提(確認事項): 素材は利用者が用意した 1 枚絵で、背景が焼き込まれている。自動の透過で縁に白っぽい滲みが残る可能性があり、その場合は、結果を見て、修正するか、利用者に透明な PNG を依頼する。砂ぼこり・星・「Zz」は半透明で、汚れが出やすい。見た目の大きさ(70 px)は、実際に見て調整する
