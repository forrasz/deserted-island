# Design

## Context

- プレイヤーの描画は、`renderer.ts` の `drawPlayer` が、スプライトシートのコマ(`player-anim.ts` の状態機械で選ぶ)を、足元をそろえて描く。左向きは、足元を軸に左右反転する。
- 投げる操作は、`game.ts` で、押した瞬間(`throw && !throwHeld`)に、ヤシの実を出して手持ちを減らす。「投げた」ことを、描画に伝える状態はない。
- 投げる専用の絵(コマ)はない。ユーザーが、「既存の絵を加工して作る」ことを選んだ。

## Goals / Non-Goals

**Goals:**
- 投げた手応えが見える短い動き(傾き・弧)と、実を持つ姿(手元の実)を付ける。
- 描画の時間割は、純粋関数にして、Vitest で検証する。

**Non-Goals:**
- 腕だけを振る細かい動き(絵の加工では、できない)。
- 新しいスプライト素材・シートの再生成。
- ヤシの実を持った状態の、専用の歩きなど。

## Decisions

1. **状態: `GameState.throwT`。** 投げた更新で 0、更新のたびに `dt` ずつ増える(ヒットストップの間は止まる)。初期値は、十分大きな値(`THROW_ANIM_TIME` より大きい 99)。描画が、これを見て、動きを決める。
   - 代案: 描画側で、`thrown.length` や `held` の変化を検出 → 拾得での増減と区別しにくく、1 フレームに複数回更新される場合に取りこぼすので、採らない。
2. **投げる動きの時刻表は純粋関数 `throwPose(t)`(`player-anim.ts`)。** 戻り値: 傾き(度。右向きを正)・横倍率・縦倍率・前へのずれ(px)・弧の濃さ。`t < 0` や `t ≥ 0.3` は動きなし(傾き 0・倍率 1・弧 0)。
   - 0 〜 0.08 秒: 傾きが 0 → 14 度(easeOut)。倍率は 1 → (1.05, 0.97)、前へ 0 → 4 px。
   - 0.08 〜 0.3 秒: smoothstep で戻る(14 度 → 0、倍率 → 1)。
   - 弧: 0 〜 0.15 秒、濃さ 0.7 → 0(線形)。
3. **描画。** コマを描く前に、足元へ `translate`、向き(左向きは反転)に合わせて `rotate(傾き × 向き)`・`scale(横, 縦)`・前へのずれを `translate` し、足元を原点にコマを描く(足元はずれない)。弧は、肩の位置(足元から上へ表示の高さの 0.6)を中心に、後ろ上から前へ、半径 40 px の弧(白・半透明)を描く。
4. **持っているヤシの実。** 手持ちが 1 個以上で、動きがやられ・被弾でないとき、手元(進む向きの前へ 16 px・足元から上へ 表示の高さの 0.55)に、半径 7 px の実を、既存の `drawCoconut` で描く。投げる動きの傾きには、実も一緒に傾ける(同じ変換の中で描く)。
5. **やられ・被弾・石の硬直の間は重ねない。** `AnimState.clip` が `hit` / `knockout` のとき、または `dead` / `stunned` のとき。
6. **フォールバック。** シートがないときは、従来の描画のまま(新しい表示なし)。

## Risks / Trade-offs

- 体の傾きだけの動きなので、腕を振る動きほど、投げた感じは出ない。弧と傾きで補う。後日、投げる絵が用意できれば、コマを差し替えられるよう、`throwPose` は描画の変換だけに閉じる。
- 実を持つ表示は、小さく、走る・ジャンプのコマの手の位置とは、ずれる(コマごとに、手の位置が違う)。位置は固定値で、見栄えを見て調整する。

## 実装での確認結果

- 弧は、肩を中心に、前方(中心を前へ 8 px ずらし、半径 34 px、角度 -1.9 〜 0.5 ラジアン)に描くと、頭の上の輪にならず、前へ振った腕に見えた。
- 右向き・左向きとも、傾き・弧・手元の実が、進む向きにそろうこと、シートがないときは従来の赤い四角のままであることを、画面で確認した。
