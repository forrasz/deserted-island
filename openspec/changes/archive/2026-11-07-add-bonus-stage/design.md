# Design

## Context

- `stepGame(state, input, dt, world)` は、本編の世界(`WorldBounds`: 幅 25800・高さ 1620・崖・穴・浮島)を引数で受け取って、プレイヤー → ボス・ザコ敵・弾 → 接触 → 部品 → 海・脱出、の順で更新する。`stepPlayer(player, input, dt, world)` も `world` を受け取るので、別の `WorldBounds` を渡せば、別の広間でも同じ移動・ジャンプの動きが使える
- `GameState` は、プレイヤー・ボス・敵・弾・部品・拾得数・HP・無敵・死亡・復帰位置・復帰ロックを持つ。被弾の値(HP -1、無敵 2 秒、跳ね上がり)は `PLAYER_INVULN_TIME` と `HIT_BOUNCE_SPEED`
- 画面遷移(`flow.ts`)は、`playing` のあいだ `stepGame` を呼ぶだけ。ボーナスを `playing` の中の状態にすれば、`Flow` の遷移(クリア・ゲームオーバー・再開)は変えずに済む
- カメラは `computeCameraX` / `computeCameraY` が、世界の幅・高さを引数で受け取る(既定は本編の大きさ)。`main.ts` が、プレイヤーの位置から計算して `Renderer.draw` に渡している
- ステージの中間地点(横幅 25800 の中央 12900)は、高所の回廊(浮島)の下にあたる、平らな地面。ここには、ザコ敵もボスの往復範囲もない(ザコ敵は 11620 まで、13880 から。ボス 5 の闘技場は 14250 から)

## Goals / Non-Goals

**Goals:**
- 本編の動き(`stepPlayer`・被弾・無敵)を使い回して、ボーナスを少ないコードで足す
- ボーナスの更新・入退場・アイテムの判定を `src/core` の純粋関数にして、Vitest で確認する
- 本編の状態を壊さず(止めて保って)、戻ったときに続きから遊べる

**Non-Goals:**
- 乱数、スコア、画像・効果音、入退場の演出、複数のボーナス(proposal 参照)

## Decisions

### 1. ボーナスは、`GameState` の中の「サブ状態」にする
`GameState` に `bonus: BonusState | null` と `bonusUsed: boolean` を足す。`bonus` が null でなければ、`stepGame` は本編を更新せず、`stepBonus` へ処理を切り替える。
- 理由: `Flow`(タイトル・プレイ・クリア・ゲームオーバー)を変えずに済む。HP・無敵・死亡が `GameState` の共通の項目なので、石の被弾でゲームオーバーにする経路も、そのまま使える
- 代替: `Flow` に `bonus` のフェーズを足す。HP などを 2 か所に持つことになり、ゲームオーバーの判定も二重になるので採らない
- `BonusState`: `{ player, items, t(経過秒), stun(残りの硬直秒), spawned(出した数), saved: { respawn } }`。`saved` に、入場時の復帰位置(`respawn`)だけを持つ。ボス・ザコ敵・弾・部品は、`GameState` の項目がそのまま残る(ボーナス中は更新しない)ので、保存は要らない

### 2. 広間は、別の `WorldBounds` として定義する
広間は `{ width: 2880, groundY: 460, height: 540 }`(`solids` 省略 = 平らな床 1 枚)。プレイヤーの更新には `stepPlayer(..., BONUS_WORLD)` を使う。落下しない(床しかない)ので、穴の処理は要らない。
- 理由: 本編と同じ重力・移動・ジャンプ・着地がそのまま使える(spec「本編と同じ操作」)
- 広間の高さ 540 は画面の高さ(`VIEW_HEIGHT`)と同じなので、縦のカメラは 0 に固定される

### 3. 入場は、隠し穴の「範囲」+ 地面に立っていること
隠し穴は `{ x: 12840, w: 120 }`(中央 12900 を中心に幅 120)。条件は、`player.onGround` かつ プレイヤーの中心 x が範囲内かつ `!bonusUsed`。見た目は普通の地面のままで、描画しない。
- 理由: 操作が左右とジャンプだけなので、「その上に立つ」が最も単純で、見つけやすさとの釣り合いが取れる。空中を通過しただけでは入らないので、ジャンプで飛び越えた人は入らない
- 入場の更新では、プレイヤーは広間の左端(`x = 100`)の床に立つ。本編の `respawn` は `bonus.saved` に保存する

### 4. 飛び出しは「スケジュール表」で、完全に決定的にする
吹き出し口は 6 か所(`x = 500, 900, 1300, 1700, 2100, 2500`)。`t = 1.0 + 0.6 * n`(n = 0, 1, 2…)の時刻に、n 番目を飛び出させる。口は `n mod 6`、種類は 8 個の表(石・ハート・石・石・ハート・石・ハート・石)の `n mod 8`、横の速度は n が偶数なら +100、奇数なら -100(px/s)。初速は上向き 950 px/s、重力は 2000(本編と同じ)。
- 理由: 乱数を使わず、同じ時刻には必ず同じものが出る(spec「決まった順番」)。`t` と `spawned` だけで決まるので、テストが書きやすい
- 試算: 飛び出しの最高点は約 225 px、空中にいる時間は約 0.95 秒。30 秒で約 49 個。ハートは 3/8 で約 18 個(HPの最大 5 に対して十分)、石は約 31 個。1 つの口は 3.6 秒に 1 回しか出さず、プレイヤーが口の近く(±150 px)を通る時間は約 1 秒なので、石に当たる確率は口ごとに 3 割程度で、見てからよけられる
- 大きさは、ハート・石とも 28×28 の矩形で判定する
- ハートは取らなければ、床に落ちて消える。石も同じ

### 5. 接触と効果
- 毎更新、プレイヤーの矩形と、生きているアイテムの矩形の重なりを調べる
- ハート: 消して `hp = min(hp + 1, PLAYER_MAX_HP)`
- 石: 無敵でなければ、消して `hp - 1`・`hitInvuln = PLAYER_INVULN_TIME`・`stun = STONE_STUN_TIME(1.5)`・小さく跳ね上げる(`HIT_BOUNCE_SPEED`)。無敵中は、何もせず通り過ぎる(消さない)。同じ更新で複数の石に重なっても、被弾は 1 回
- 硬直中は、プレイヤーの更新に `NO_INPUT` を渡す(本編の `respawnLock` と同じやり方)。重力は働く
- `hp` が 0 になれば `dead = true`。`flow.ts` の既存の判定でゲームオーバーになる
- 本編の被弾(`resolveBossContact` など)は呼ばない

### 6. 退場
`t >= BONUS_DURATION(30)`、またはプレイヤーの右端が `BONUS_WORLD.width - 40` 以上(出口)のとき、`bonus = null`・`bonusUsed = true` にし、プレイヤーを隠し穴の中央に立たせ、`saved` の復帰位置を戻す。戻る位置は、隠し穴の中央に立つ位置(`x = 12900 - PLAYER_WIDTH / 2`、地面の上)。`bonusUsed = true` なので、再入場はしない。`hp`・`hitInvuln` はボーナス中の値を引き継ぐ(本編の項目を共用しているので、コピー不要)。
- 入場前の位置を保存せず、戻る位置は常に隠し穴の中央に統一する(入場は隠し穴の範囲の中で起きるので、入場前の位置とほぼ同じ。spec「地上の隠し穴の位置へ戻る」に合わせる)

### 7. カメラと描画
- カメラは、`computeCameraX(center, VIEW_WIDTH, BONUS_WORLD.width)` と `computeCameraY(..., BONUS_WORLD.height)`(= 0)で決める。どの世界を使うかは、`GameState.bonus` の有無で、`main.ts` が切り替える(小さな関数 `cameraOf(game)` を `src/core/camera.ts` に置いて、Vitest で確認する)
- `Renderer.draw` は、`game.bonus` があれば、本編の描画をせずに、ボーナスの描画をする: 暗い地下の背景、床、ハート(赤い図形)・石(灰色の図形)、プレイヤー(無敵・硬直の点滅は本編の仕組みを再利用)、HP、残り時間、入場の 2 秒間の案内
- 描画の判定は `src/platform` に置き、ロジックは `src/core/bonus.ts` に置く

### 8. ステージの検査
`stage-check.ts` の `validatePlacements` に、隠し穴が「平らな地面の上」かつ「ザコ敵・ボスの往復範囲(大きさを含む)と重ならない」ことの検査を足す。違反があれば、Vitest が落ちる。

## Risks / Trade-offs

- **隠し穴が見つからない**: 目印を出さないので、README のヒント頼りになる。見つけたい人のために、README に「中間地点の高所の回廊の下」とだけ書く。入れなくても、ゲームの進行には影響しない(ボーナスは任意)
- **偶然入る**: 回廊の浮島の上を進む限りは通らないが、浮島から落ちて地面に着くと入りうる。ボーナスは害がない(石で最悪HPが減るが、ハートで回復もできる)ので許容する
- **HPが 1 で入ると、石で死ぬ**: spec のとおり、ゲームオーバーになる。リスクを伴う遊びとして意図している。回避は可能なので、バランスは手動のプレイで見て、必要なら硬直や頻度を調整する(spec も更新する)
- **`GameState` の型変更**: 状態を直接組み立てているテストが増えるが、既定値(`bonus: null`・`bonusUsed: false`)で足りる。型チェックで漏れを検出できる
- **ボーナス中の本編の凍結**: `stepGame` の冒頭で分岐するので、本編の更新の順序は変えない。ボーナス中に `projectiles` などが残るが、描画しないので見えない
