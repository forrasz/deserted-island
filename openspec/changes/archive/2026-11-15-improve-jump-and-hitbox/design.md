# Design

## Context

- `stepPlayer`(`src/core/player.ts`)は、毎更新、`vx = (右 - 左) * MOVE_SPEED` を決め直している。地上でも空中でも同じなので、空中で向きを変えたり、止まったりできる。ジャンプは、地面(`onGround`)で `vy = -JUMP_SPEED`、重力 2000、頂点は約 140 px、滞空は約 0.75 秒、水平に最大約 210 px
- ステージの到達可能性の検査(`stage-check.ts` の `canTransit`)は、「一方向に押し続け、1 回だけジャンプを押す」入力で、`stepPlayer` を回して調べている
- 被弾は、`enemy-contact.ts`(ザコ敵)・`projectile.ts`(弾)で、`overlaps(playerRect, 相手の矩形)`。踏みつけは `isStomp(prevPlayer.y, vy, 相手の上辺)`(`STOMP_TOLERANCE = 8`)。ボスは `game.ts` の `resolveBossContact`(押し戻しと被弾)。プレイヤーは 40×56、ザコ敵は 40×40、弾は 24 px。いずれも見た目の矩形がそのまま当たり判定
- 跳ね返り(`STOMP_BOUNCE_SPEED`)と跳ね上がり(`HIT_BOUNCE_SPEED`)は、`game.ts` などが `vy` と `onGround` だけを書き換えるので、`vx` は、プレイヤーの直前の値のまま残る

## Goals / Non-Goals

**Goals:**
- 空中の水平の動きを、踏み切りで確定する(軌道が放物線になる)
- ザコ敵・弾との被弾を、掠りにくくする。ただし、踏みつけの感触は変えない
- 既存の変更を小さく保つ(`stepPlayer` の `vx` の決め方と、2 つの接触判定だけを変える)

**Non-Goals:**
- HP・無敵時間・踏みつけの許容・ボスの体との接触・ボーナスの石の見直し、ジャンプの高さ・速さ・可変ジャンプ、判定の描画(proposal 参照)

## Decisions

### 1. 水平の速さは、「地上にいたか」で決める
`stepPlayer` の冒頭で、`grounded = player.onGround`(この更新の開始時点)を見る:
- `grounded`: `vx = dir * MOVE_SPEED`(これまでどおり。ジャンプする更新も、ここで速さが決まる = 踏み切りで確定)
- そうでない(空中): `vx = player.vx`(前の更新の速さのまま。キーは見ない)
- 水平の移動のあと、空中のとき、崖の側面・ワールドの端で、予定の移動量より実際の移動量が小さければ(押し返されたなら)、`vx = 0` にする
- 理由: ジャンプする更新は、まだ `onGround` が真なので、そのときの入力がそのまま踏み切りの速さになる。地上から歩いて落ちたときは、その速さが残る。跳ね返り・跳ね上がりは、`vy` と `onGround` だけを書き換えるので、水平の速さは、直前の値(= 空中なら踏み切りの速さ)のまま残る
- 代替: 空中で弱い加速を許す(慣性つきの空中制御)。「空中で操作を変えられるのが不自然」という要望に合わないので、今回は採らない。必要なら、あとから足せる
- 地面に着地した更新は、空中として処理される(速さが保たれる)。次の更新から、地上の入力になる

### 2. 到達可能性の検査は、変えずに通る見込みで、テストで確認する
`canTransit` の入力は「一方向に押し続け、1 回だけジャンプ」なので、踏み切りの更新で、押している向きの速さが決まり、そのまま空中を進む。到達する位置は、これまでと同じになる。実際に、既存のステージの検査(`stage.test.ts` など)がすべて通るかを、最初に確認する。通らなければ、ステージを調整する(その場合は、proposal を見直す)
- 空中で向きを変えて到達していた区間が、ステージにないことを、この検査が保証する(ステージは、押し続け + 1 回のジャンプで通れる前提で作られている)

### 3. 被弾判定の矩形を、別に定義する
- `config.ts`: `PLAYER_HURT_WIDTH = 28`・`PLAYER_HURT_HEIGHT = 46`・`ENEMY_HURT_SIZE = 32`
- `contact.ts`: `playerHurtRect(p)` = `{ x: p.x + (40 - 28) / 2, y: p.y + (56 - 46), w: 28, h: 46 }`(下辺と左右の中心をそろえる)
- `enemy.ts`: `enemyHurtRect(e)` = `{ x: e.x + (40 - 32) / 2, y: e.y + (40 - 32), w: 32, h: 32 }`
- `enemy-contact.ts`: 次の順に判定する(これまでと同じ順序で、判定の矩形だけを分ける)
  1. 見た目の矩形どうしが重なり、かつ `isStomp` → 踏みつけ(倒す・跳ね返る。被弾しない)
  2. それ以外で、被弾判定どうしが重なる → 被弾の候補
  - 同じ更新で、どれかの敵を踏んだら、被弾しない(既存どおり)
- `projectile.ts`: `resolveProjectileContact` は、`playerHurtRect` と弾の矩形(そのまま)で判定する
- ボス(`resolveBossContact`)・部品・ボーナスの石とハートは、見た目の矩形のまま(変えない)
- 理由: 踏みつけは「上から落ちた」ことの判定なので、見た目の矩形のほうが自然で、取りこぼしがない。被弾だけを小さくすれば、「踏んだのに倒せない」を増やさずに、掠りを減らせる

### 4. 数値は、遊びながら調整できるようにする
被弾判定の大きさは、定数 3 つだけにして、変えやすくする(変えたら、spec の数値も更新する)。

## Risks / Trade-offs

- **被弾が増える側の副作用**: 空中で、ザコ敵の近くの着地点を避けられなくなる。被弾判定を小さくすることで、相殺する想定だが、実際に動かして確かめる。バランスが悪ければ、被弾判定の大きさ、または空中の弱い加速(案 B)を検討する
- **ステージの到達可能性**: 上記のとおり、検査は変えずに通る見込みだが、確認する。柱とヌシの戦い(気絶したヌシの上へ跳んで踏む)は、踏み切りの位置の精度が要る(ボットで確認する)。ボーナスの広間も、同じ `stepPlayer` なので、石のよけ方が変わる(石は見てから跳べば、よけられる)
- **跳ね上がりでの水平の速さ**: 被弾の跳ね上がりでも、水平の速さが残るので、被弾した方向へ流れる。無敵の間は、敵を通り抜けるので、害は小さい。違和感があれば、被弾時に水平の速さを 0 にする(別の判断)
- **既存テストの調整**: 空中でキーを変えるテストと、重なりを 10 px にしているザコ敵のテスト(被弾判定が小さくなり、重ならなくなる)が、調整の対象になる。型は変わらない
- **被弾判定が見えない**: 見た目と判定がずれることを、プレイヤーは見られない。判定を小さくしても、「触れていないのに当たった」とは、起きにくい(判定が見た目の内側にあるため)
