# Proposal

## Why

現在は「ボスを倒して部品を拾う」ところまでしかなく、ゲームに始まりも終わりもない。
脱出条件(イカダを完成させて海へ出る)を実装し、タイトルからクリアまでを通して遊べるようにして、脱出ゲームとして一通り成立させる。

## What Changes

- イカダの完成: 部品を必要数(1 個)そろえるとイカダが完成する。完成したことを画面に表示する
- 海と脱出: ワールドの右端に海を配置する。イカダが未完成の間、プレイヤーは海に入れず(砂浜で止まる)、案内を表示する。イカダ完成後に海へ到達すると脱出に成功する
- ゲームフロー: タイトル画面 → プレイ → クリア画面 → もう一度プレイ、の遷移を実装する。決定キーは Enter キー
- タイトル画面とクリア画面を、図形とテキストで表示する
- クリア画面から再プレイすると、ボス・部品・所持数・プレイヤー位置がすべて初期状態に戻る
- 遷移・イカダの完成・海の通行制限・脱出の判定は、`src/core` の純粋な TypeScript とし、Vitest でテストする
- **含めないもの**:
  - プレイヤーのHP、ダメージ、ゲームオーバー
  - ボスや部品の複数化
  - リアルなキャラクター(画像の読み込みと素材の差し替えは、別の change で扱う)
  - サウンド、タイム計測、スコア、セーブ

## Capabilities

### New Capabilities
- `escape-goal`: イカダの完成、海の通行制限(イカダ未完成なら砂浜で止まる)、イカダ完成後に海へ到達して脱出する判定、およびそれらの表示
- `game-flow`: タイトル → プレイ → クリア → 再プレイの遷移、各画面の表示、再プレイ時の初期化

## Impact

- 新規コード: `src/core/` にフロー管理(フェーズと遷移)とイカダ・海・脱出のロジックとテスト
- 変更するコード: `InputState` に決定キー(`confirm`)を追加、`GameState` にイカダ・脱出の状態を追加、`stepGame` に海の通行制限と脱出判定を追加、`src/platform/keyboard.ts` に Enter を追加、`src/platform/renderer.ts` に海・イカダ・案内・タイトル・クリア画面を追加、`src/main.ts` をフロー経由に変更
- 既存 spec への影響なし。新しい定数(必要部品数 1、海の開始位置)は `config.ts` に追加する
- 新規依存関係: なし
- 前提(確認事項): 「キャラクターをリアルにする」要望は、素材の調達方法の判断が必要なため、別の change で扱う。本 change は引き続き図形で表示する
