# Design

## Context

- `stepPlayer`(`src/core/player.ts`)は、いまは次のとおり。地上: `vx = dir * MOVE_SPEED`(即座に最高速・即座に停止)。空中: `vx = player.vx`(踏み切りの速さのまま、キーを見ない。壁にぶつかると 0)。ジャンプ: `input.jump && onGround` の更新で `vy = -750`(1 回押しただけでも、最大の高さまで上がる)。重力 2000。頂点約 140 px、滞空約 0.75 秒、全速で約 210 px
- `Player` は `{ x, y, vx, vy, onGround }`。`stepPlayer` は、引数の `player` と `input` だけから次の状態を作る(純粋)。落下・踏みつけの跳ね返り(`vy = -600`)・被弾の跳ね上がり(`vy = -350`)は、`game.ts` などが `vy` と `onGround` だけを書き換える
- ステージの到達可能性の検査(`stage-check.ts` の `attempt`)は、`jump: t === jumpTick`(1 更新だけ押す)で `stepPlayer` を回し、右(または左)を押し続ける入力で調べている
- 前の変更で、空中の操作を無くしたところ、着地点の修正ができず、難しくなった(proposal 参照)

## Goals / Non-Goals

**Goals:**
- スーパーマリオの、慣性のある移動・可変ジャンプ・入力の猶予を、`stepPlayer` の中だけで実現する
- ジャンプの最大の高さ(約 140)と、全速で押し続けたときの最大の距離(約 210)を保ち、ステージを作り直さずに済ませる
- すべての数値を `config.ts` の定数にして、遊びながら調整できるようにする

**Non-Goals:**
- 重力の非対称化(落下を速くする)、二段ジャンプ・壁ジャンプ・ダッシュ、HP・被弾判定の見直し(proposal 参照)

## Decisions

### 1. 水平の速さは、「approach」(目標へ、決まった量だけ近づく)で決める
`approach(v, target, delta)` = v を target へ、最大 delta だけ近づける。1 更新の `delta = 加速度 * dt`。目標は `dir * MOVE_SPEED`(dir は -1・0・+1)。
- **地上**(更新の開始時に `onGround`):
  - キーなし: 目標 0、`GROUND_DECEL = 2400`
  - 進んでいる向きと反対のキー(`vx` の符号 ≠ dir かつ `vx ≠ 0`): `TURN_ACCEL = 3600`
  - それ以外(同じ向き・停止から): `GROUND_ACCEL = 1800`
- **空中**:
  - キーなし: 速さは変えない(減速しない)
  - キーあり: 目標 `dir * MOVE_SPEED`、`AIR_ACCEL = GROUND_ACCEL * 0.6 = 1080`(向きを変えるときも、同じ強さ)
- 理由: 1 つの小さな関数で、ground / air の違いが「加速度」と「キーなしのときの扱い」だけになる。数値を定数で変えられる
- ジャンプする更新は、まだ地上として扱う(踏み切りの更新の速さは、地上の加速のあとの値。そのまま空中へ引き継がれる)
- 壁・ワールドの端に阻まれたとき(予定の移動より実際の移動が小さい)は、地上でも空中でも、`vx = 0`(押し続けて速さをためないため。前の変更では、空中だけだったのを、地上にも広げる)
- 代替: 地上は従来どおり即座に動く(加速なし)。proposal で「地上の加速・減速」を選んだので採るが、定数を大きくすれば、従来に戻せる

### 2. 可変ジャンプは、「キーを離したら、上向きの速さを打ち切る」で実現する
更新ごとに、`input.jump` が偽で `vy < -JUMP_CUT_SPEED(400)` なら、`vy = -400` にする(重力の加算の前)。
- 押し続ける間は、従来どおり初速 -750(頂点約 140)。離した更新から、-400 に打ち切られ、そこから重力で上昇が止まる。最小のジャンプ(1 更新だけ押す)は、約 40 px 程度(打ち切り -400 の頂点 = 400² / 4000 = 40 px に、離すまでの更新ぶんが足される)
- 踏みつけの跳ね返り(-600)にも、同じ規則が働く。キーを押していれば高く(約 90 px)、離していれば -400(約 40 px)。被弾の跳ね上がり(-350)は、打ち切りの閾値より小さいので、影響を受けない
- 下降中(`vy > 0`)は、何も変えない
- 理由: `Player` に、ジャンプ中かどうかの状態を足さずに済む。重力は変えないので、押し続けたときの軌道は、今と完全に同じ(ステージはそのまま通れる)

### 3. 入力の猶予は、`Player` の省略可能な項目 2 つで持つ
`Player` に `coyote?: number`(足場を離れてからジャンプできる残り秒)と、`jumpBuffer?: number`(先行入力の残り秒)を足す(省略時は 0。既存のテストの `Player` のリテラルは、変えずに済む)。
- **コヨーテタイム**: 地上のあいだは `coyote = COYOTE_TIME(0.1)` に保つ。空中では `dt` ずつ減らす。ジャンプできるのは `onGround || coyote > 0`。ジャンプしたら `coyote = 0`(二重ジャンプを防ぐ)。歩いて落ちたときは、0.1 秒ぶん残る
- **先行入力**: 空中で、ジャンプできない状態でスペースが押されていたら `jumpBuffer = JUMP_BUFFER(0.1)`、そうでなければ `dt` ずつ減らす。地上で `jumpBuffer > 0` なら、キーが離れていても、その更新でジャンプする(ジャンプしたら 0)。押しっぱなしの連続ジャンプ(既存の「長押しでの連続ジャンプ」)も、この仕組みで従来どおり成立する
- 跳ね返り・被弾で `vy` が外から書き換えられたとき、`coyote` は 0 でないかもしれない(地上のあいだに満たされた値が残っている)。空中へ出た更新から減るので、0.1 秒以内に限られ、悪用はできない(跳ね返った直後の 0.1 秒は、空中でジャンプできるが、踏みつけ直後なので、許容する)。違和感があれば、外から `vy` を書き換える箇所で `coyote = 0` にする

### 4. 到達可能性の検査は、ジャンプを押し続ける入力にする
`attempt` の入力を `jump: t >= jumpTick && t < jumpTick + JUMP_HOLD_TICKS` に変える(上昇の間、押し続ける。`JUMP_HOLD_TICKS = 50` で、約 0.83 秒 > 上昇の 0.375 秒)。検査の意味(「一方向に押し続け、1 回だけジャンプを押す」)は変わらず、人間が再現できる範囲のまま。地上の加速があるので、助走が短いと、最高速に達しない。助走の位置(最大 420 px 手前)を試すので、通常のステージは通る見込み。通らない区間があれば、原因を調べて報告する

### 5. 数値は、定数にまとめる
`config.ts`: `GROUND_ACCEL = 1800`・`GROUND_DECEL = 2400`・`TURN_ACCEL = 3600`・`AIR_ACCEL_RATIO = 0.6`(空中の加速 = 地上の加速 × 0.6)・`JUMP_CUT_SPEED = 400`・`COYOTE_TIME = 0.1`・`JUMP_BUFFER = 0.1`。`MOVE_SPEED`・`JUMP_SPEED`・`GRAVITY` は変えない。

### 6. 描画・入力・他の仕組み
- 入力(`InputState`)は変えない。`jump` は押している間 true(キーボードも、タッチのボタンも、同じ)
- 穴からの復帰(`game.ts`)は、`{ x, y, vx: 0, vy: 0, onGround: true }` で作り直しているので、猶予は 0 に戻る
- ボーナスの広間も、同じ `stepPlayer` を使うので、同じ操作感になる(石のよけ方が変わる)
- ボス戦(気絶したヌシを踏む): ジャンプの高さは、押している時間で決まる。かがんだヌシの上辺(地面から 100)へ着地するには、約 100 px 以上の高さが必要で、押し続ければ達成できる

## Risks / Trade-offs

- **既存テストの調整が多い**: 地上で、キーによる即座の動き・停止を前提にしたテスト(移動距離が `速さ × 時間` のもの)、ジャンプ入力を 1 回だけ与えて最大の高さを前提にしたテスト(ジャンプの高さ・ステージの通し・ボット)が、調整の対象になる。`Player` の型は、省略可能な項目だけを足すので、リテラルは変えずに済む
- **地上の加速・減速で、細かい位置合わせがやや難しくなる**: 約 0.16 秒の加速と、約 17 px の滑りなので、小さいが、ザコ敵の手前で止まるときなどに効く。操作しにくければ、`GROUND_ACCEL` と `GROUND_DECEL` を大きくして(例: 1e9)、従来の即座の動きに戻せる
- **空中での軌道修正が、前々回(完全に自由)より弱い**: 地上の 6 割で、急には向きを変えられない。前々回の不満(不自然)と、前回の不満(難しい)の、中間を狙う
- **ジャンプの最小の高さ(約 40 px)**: 低すぎれば、`JUMP_CUT_SPEED` を上げる(500 で約 62 px)。数値は、遊びながら調整する
- **押しっぱなしの連続ジャンプ**: 先行入力があるので、押し続けていると、着地の瞬間に必ず再ジャンプする。意図せず跳ぶことがあるが、既存の仕様どおり
- **ステージの検査が通らない可能性**: 通らない区間があれば、原因を調べて報告し、数値(加速度など)を見直す。ステージ側は、まず変えない
