# Proposal

## Why

ゲームを GitHub Pages で公開したが、操作がキーボードだけで、スマホでは遊べない。画面も 16:9 の横長を前提にしていて、スマホの縦向き・ブラウザの標準動作(スクロール、拡大、長押しメニュー)に邪魔される。スマホの横向きで、画面上のボタンだけで最後まで遊べるようにする。

## What Changes

- **タッチ操作**: 画面の左に「◀」「▶」、右に「ジャンプ」のボタンを重ねて表示し、押している間だけ移動・ジャンプの入力にする。複数の指を同時に使える(◀を押したままジャンプ)。ボタンはタッチ操作ができる端末(`pointer: coarse`)でだけ表示し、PC では表示しない
- **決定のタッチ操作**: タイトル・クリア・ゲームオーバーの画面では、画面のどこかをタップすると、`Enter` と同じ決定として扱う。プレイ中のタップは決定として扱わない
- **画面の調整(横向き専用)**:
  - 画面の向きが縦のときは、ゲームを止めて「横向きにしてください」と案内を出し、横向きに戻したら再開する
  - ゲーム画面は、スマホの横向きの画面いっぱいに、16:9 の比率を保って収める(切り欠きなどの安全領域を避ける)
  - ボタンの長押しや連打で、ブラウザのスクロール・拡大・長押しメニュー・文字選択が起きないようにする
- 入力の判定(ボタンの押下状態から `InputState` への変換、向きの判定)は `src/core` の純粋な TypeScript として切り出し、Vitest でテストする。DOM のイベントとボタンの表示は `src/platform` に置く
- `README.md` にスマホでの遊び方を追記する
- **含めないもの**:
  - 縦向きでの対応、PWA(ホーム画面に追加・オフライン対応)、全画面 API の強制
  - ボタンの位置・大きさをユーザーが変える設定、振動、効果音
  - ゲームの内容(敵・ボス・ステージ・難易度)の調整
  - 実機での検証(開発環境のタッチエミュレーションで確認し、実機は公開後にユーザーが確認する)

## Capabilities

### New Capabilities
- `touch-controls`: 画面上のボタン(◀・▶・ジャンプ)と、画面タップによる決定を、ゲームの入力(`InputState`)に変換する。複数同時押し、指を離したときと中断時の解除、表示する端末の条件を定める
- `mobile-display`: 縦向きの案内とゲームの一時停止、横向きでの画面いっぱいの表示、ブラウザの標準動作(スクロール・拡大・長押しメニュー・選択)の抑止を定める

## Impact

- 新規コード: `src/core/touch.ts`(ボタンの状態 → 入力、向きの判定)とそのテスト、`src/platform/touch.ts`(ボタンの DOM と Pointer Events)
- 変更するコード:
  - `src/main.ts`: キーボードとタッチの入力を合成する。縦向きの間は更新を止める。フェーズに応じて決定のタップを有効にする
  - `index.html`: `viewport` の設定(拡大の禁止・`viewport-fit=cover`)、ボタンと縦向き案内の要素、スマホ向けの CSS
  - `src/platform/renderer.ts`: 画面サイズの追従(必要な場合のみ)
  - `README.md`
- 既存テストへの影響: ほぼなし(入力の型 `InputState` は変えない)
- 新規依存関係: なし
- 前提(確認事項): ボタンの見た目は図形と文字だけ(画像素材なし)。実機の機種ごとの差(ブラウザのツールバー、ノッチ)は、安全領域の指定とエミュレーションで対応し、実機での微調整は公開後に行う
