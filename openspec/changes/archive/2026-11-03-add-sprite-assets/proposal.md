# Proposal

## Why

現在のキャラクターや背景はすべて単色の図形で、無人島・海・イカダ・敵・人間といった世界観が伝わらない。
実写に近いリアルな見た目にするため、画像素材を読み込んで描画できるようにする。素材の用意は利用者が行うので、素材がなくても今の図形で動き続け、素材を少しずつ差し替えられる仕組みにする。

## What Changes

- 画像素材(PNG)を、決められたファイル名で `public/assets/` に置くと、起動時に読み込んで描画に使う
- 対象の素材: プレイヤー(人間)、ボス(カクレモモジリ)、イカダの部品、完成したイカダ、背景(無人島の風景)、砂浜の地面、海
- 素材のファイルがない、または読み込みに失敗した場合は、そのキャラクター・領域だけ現在の図形に戻す。ゲームは常に遊べる
- 画像は当たり判定の矩形に合わせて表示する(縦横比を保ち、矩形の高さに合わせて拡大縮小し、足元を揃える)。当たり判定そのものは変更しない
- プレイヤーとボスは、進行方向に合わせて画像を左右反転する(素材は右向きで描かれている前提)
- 背景は、カメラの動きより遅くスクロール(視差)させる。地面と海はワールド座標に沿って繰り返し(タイル)表示する
- 必要なファイル名・推奨サイズ・向き・透過の条件を `public/assets/README.md` に記載する
- 向きの判定と素材の定義は `src/core` の純粋な TypeScript とし、Vitest でテストする。画像の読み込みと描画は `src/platform`
- **含めないもの**:
  - 素材そのもの(画像ファイル)の作成・取得。Web 上の画像の収集やダウンロードは行わない
  - 歩行などのアニメーション(スプライトシート)
  - プレイヤーのHP、死亡、ゲームオーバー、敵の追加(次の change で扱う)
  - タイトル画面・クリア画面・HUD の画像化、サウンド

## Capabilities

### New Capabilities
- `sprite-assets`: 画像素材の定義(キーとファイル名)、起動時の読み込み、読み込み失敗時の図形へのフォールバック、素材の仕様書き
- `sprite-rendering`: 素材を使ったプレイヤー・ボス・部品・イカダ・背景・地面・海の描画、当たり判定矩形への合わせ方、向きによる左右反転、背景の視差

### Modified Capabilities
- `player-movement`: 「地面とプレイヤーを表示する」要件。プレイヤーの表示を「四角形」固定から「素材があれば画像、なければ四角形」に変更する
- `boss-enemy`: 「ボスの配置と表示」要件。ボスの描画を「プレースホルダー図形」固定から「素材があれば画像、なければ図形」に変更する

## Impact

- 新規コード: `src/core/assets.ts`(素材キーとファイル名)、`src/core/facing.ts`(向きの判定)とテスト、`src/platform/assets.ts`(画像の読み込みとフォールバックの判定)
- 変更するコード: `src/platform/renderer.ts`(素材描画とフォールバック)、`src/main.ts`(読み込みを待ってから開始)、`README.md`
- 新規ファイル: `public/assets/README.md`。画像ファイルはリポジトリに含めない(利用者が置く)
- 既存 spec への影響: 上記2要件の変更のみ。`player-movement` の Purpose 文中の「(四角形)」は delta では変更できないため、アーカイブ後に main spec を直接直す
- 新規依存関係: なし
- 前提(確認事項): 素材の権利は利用者が確認する。こびとづかんを含め、既存キャラクターの画像を利用する場合は、権利の扱いを利用者の責任で判断する
