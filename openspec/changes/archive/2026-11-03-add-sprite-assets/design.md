# Design

## Context

- 現状: `src/platform/renderer.ts` がすべてを図形(単色の四角形と線)で描画している。ロジック(`src/core`)は描画に依存しない。
- 動機とスコープは proposal.md、要件は specs(`sprite-assets` / `sprite-rendering` と、変更する `player-movement` / `boss-enemy`)を参照。
- 素材(画像ファイル)は利用者が用意する。リポジトリには含めず、素材がなくても今まで通り遊べることが前提。

## Goals / Non-Goals

**Goals:**
- 素材を置くだけで見た目が差し替わり、置いていない部分は図形のまま残る仕組みにする
- 当たり判定・ゲームロジックは一切変えない(描画だけの変更)
- 向き・配置・視差・タイルの計算を純粋な関数にして、Vitest で検証できるようにする

**Non-Goals:**
- 素材の作成・取得(Web 上の画像の収集を含む)
- アニメーション(スプライトシート)、HUD・タイトル・クリア画面の画像化
- プレイヤーのHP・敵の追加(次の change)

## Decisions

### 1. 構成: 定義と計算は `core`、読み込みと描画は `platform`
```
src/core/
  assets.ts          # AssetKey、ファイル名、読み込みの待ち時間の上限
  facing.ts          # Facing(右=1, 左=-1)、nextFacing(prev, vx)
  sprite-layout.ts   # fitToBox / parallaxOffset / tileStartX
src/platform/
  assets.ts          # loadAssets(): 画像の読み込みと AssetStore
  renderer.ts        # AssetStore を使った描画とフォールバック
src/vite-env.d.ts    # import.meta.env の型(vite/client)
public/assets/README.md   # 素材の仕様(利用者向け)
```

### 2. 素材の置き場所とファイル名
- Vite の `public/assets/` に置く。配信パスは `import.meta.env.BASE_URL + 'assets/<ファイル名>'`。
- ファイル名は固定: `player.png` / `boss.png` / `part.png` / `raft.png` / `background.png` / `ground.png` / `sea.png`。
- PNG 限定にして、拡張子の分岐やフォーマット判定を持たない。
- `public/assets/README.md` に、用途・推奨サイズ・向き・透過・継ぎ目の条件を表で記載する。Vitest で、この README に定義の全ファイル名が載っていることを検査する(定義と説明のずれの防止)。

| ファイル | 用途 | 推奨サイズ(目安) | 条件 |
|---|---|---|---|
| player.png | プレイヤー(人間) | 200×280(縦長 5:7) | 透過、右向き、足元が下端 |
| boss.png | ボス | 400×500(4:5) | 透過、右向き、足元が下端 |
| part.png | イカダの部品 | 128×128 | 透過 |
| raft.png | 完成したイカダ | 640×192(10:3) | 透過、横から見た図 |
| background.png | 背景(無人島の風景) | 高さ 540、幅は任意(例 1920) | 左右が継ぎ目なくつながる |
| ground.png | 砂浜の地面 | 256×80 | 左右が継ぎ目なくつながる、上端が地面の表面 |
| sea.png | 海 | 256×80 | 左右が継ぎ目なくつながる、上端が水面 |

### 3. 読み込み: 全部の結果が出るまで待ち、失敗は「ない」として扱う
- `loadAssets()` が各画像を `Image` で読み込み、`load` で成功、`error` または待ち時間(5 秒)の超過で失敗とする。全素材の結果が出てから `AssetStore` を返し、`main.ts` はその後にゲームループを開始する。
- `AssetStore.get(key)` は、成功した画像、または `null` を返す。`null` なら、`renderer.ts` はその対象を従来の図形で描画する。
- 起動時の待ちが最長 5 秒あるが、素材がなければ 404 が即座に返るのでほぼ待たない。ローカル配信が前提なので許容する。
- 代替: 読み込みを待たずに開始し、読み込めたものから差し替える案は、見た目が途中で切り替わるため却下。

### 4. 描画の合わせ方: 矩形の高さに合わせ、縦横比を保つ
- `fitToBox(img, box)`: 高さを box の高さに合わせ、幅は縦横比から算出。水平は box の中央、下辺は box の下辺に揃える。結果の矩形が box より広くてもはみ出して描く(spec のシナリオ)。
- 当たり判定の矩形(`PLAYER_*`、`BOSS_*`、`PART_*`)は変更しない。見た目が大きい素材は、判定より広く表示される(足元が揃うので違和感を抑えられる)。
- 完成したイカダ(`raft.png`)は、専用の描画枠 160×48 を使う(図形のフォールバックの 100×14 とは別)。位置は砂浜の端(右端が `SEA_X - 20`)。

### 5. 向き: `facing.ts` の純粋関数 + 描画側で保持
- `nextFacing(prev, vx)`: `vx > 0` なら右(1)、`vx < 0` なら左(-1)、0 なら `prev`。
- プレイヤーの向きは `Renderer` が前回の値を保持し、`player.vx` で更新する。ボスは `boss.vx` で決める(往復で常に非 0。停止中は前回の向きを保つ)。
- 左向きは `ctx.scale(-1, 1)` で左右反転して描く。素材は右向きで描かれている前提。
- 代替: `Player` に `facing` を持たせる案は、ロジックの型とテストの変更が広がるため却下(表示だけの関心事)。

### 6. 背景・地面・海
- 背景: 画像の高さを画面の高さ(540)に合わせ、幅は縦横比から算出。`parallaxOffset(cameraX, 0.2, 幅)` が `-(cameraX × 0.2)` を画像幅で折り返した位置(区間 (-幅, 0])を返し、そこから横に並べて画面を覆う。
- 地面・海: 画像の高さを地面の帯(`GROUND_Y` から画面下端、80px)に合わせ、`tileStartX(cameraX, タイル幅)` = `-(cameraX mod タイル幅)` から並べる。継ぎ目がワールド座標に固定される。地面は `0 〜 海の画面位置`、海は `海の画面位置 〜 画面右端` にクリップする。
- 素材がある場合は、従来の地面の色・草の帯・目印の縦線は描かない。ない場合は従来どおり。

### 7. フォールバックは「対象ごと」
- 7 種の素材を独立に判定する(プレイヤーだけ、背景だけ、などの部分的な導入が可能)。体力バー・HUD・案内の文字は素材と無関係に描く。
- 空の色(背景なし)、地面の色と目印(地面なし)、海の青(海なし)も同様に個別。

### 8. ロジックへの影響
- `src/core` のゲームロジック(`game.ts` ほか)は変更しない。変更は `renderer.ts` / `main.ts` / 新規ファイルのみ。
- 既存テストへの影響なし。

## Risks / Trade-offs

- [素材の縦横比が当たり判定とかけ離れていると、見た目と当たりがずれる] → README に推奨の縦横比と「足元が下端」の条件を明記する。判定は変えず、画像は高さ基準で合わせる。
- [大きい画像で読み込みが遅くなる/メモリを使う] → README に推奨サイズを記載。待ち時間の上限(5 秒)で起動が止まらないようにする。
- [素材が右向き前提なので、左向きの素材を置くと逆向きになる] → README に明記する。反転の設定は今回は持たない(必要なら別の change)。
- [継ぎ目のある背景・地面・海でタイル境界が目立つ] → README に「左右が継ぎ目なくつながる」条件を明記する。
- [素材の権利] → 素材は利用者が用意し、権利の確認も利用者が行う前提。画像ファイルはこの change では扱わず、リポジトリにも含めない。

## Open Questions

- 視差の割合(0.2)、イカダの描画枠(160×48)、推奨サイズは、実際の素材を置いて調整する(spec の要件には影響しない)。
